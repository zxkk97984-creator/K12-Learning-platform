# 一道难题吓不倒会拆解的人

「做一个接苹果游戏」听起来好难：要苹果掉下来，要碗左右移动，还要计分……可程序员看到大任务时，第一反应不是害怕，而是掏出剪刀——把大任务剪成小块。苹果的任务是往下掉；碗的任务是听指挥移动；记分牌的任务是加分。一句话的愿望，变成了三份清楚的小工作单。这种本领叫拆解问题，它是编程思维的第一个法宝。

# 把步骤说清楚

第二个法宝是把每件事说成一步一步的指令。泡面的步骤是：烧水、放面、等三分钟、调味、开吃。顺序不能乱——先放面再烧水就闹笑话了。给计算机下命令也一样：先说清做什么，再说清按什么顺序做。

试试这个游戏：让同学背对你刷牙，你口头指挥他的每个动作。「刷牙」两个字可不行——得说「拿起牙刷」「挤黄豆大的牙膏」「放进嘴里」「来回刷」。你会发现，把一件熟悉的事说成精确的步骤，比想象中难多了。而这正是编程每天在做的事。

# 找规律，偷个懒

第三个法宝最讨人喜欢：发现重复，就让计算机替你干活。画十个圆圈，不需要写十遍「画圆」，只要说「画一个圆，重复十次」。游戏里苹果不停下落，靠的就是一块「重复执行」积木不知疲倦地工作。

会找规律的人做事特别省力。数一数 1 加到 100，笨办法是一个个加，聪明的办法是发现 1 和 100 是一对、2 和 99 是一对，一共五十对，每对都是 101，答案立刻出来：5050。

# 第四个法宝之外：会提问也是本事

遇到解决不了的问题，程序员还有一个共同习惯：向别人请教时先把问题说清楚。「我的游戏苹果不掉下来了」帮不上忙；「我用了重复执行积木让苹果往下掉，点击绿旗后其他角色都动了，只有苹果没反应」——后半句话几乎等于答案自己跳出来了。

描述问题的过程就是整理思路的过程：哪里该动没动？哪里不该动却动了？改动过什么？很多问题在说清楚的那一刻就解决了。所以别怕提问，先练把问题讲明白，这是比写代码更早需要掌握的本领。

# 试错不可怕

第四个法宝藏在每次出错里。程序不听话时，程序员不会发脾气，而是像侦探一样排查：哪块积木没连上？数字是不是填错了？找到问题、修好、再试一次。错误不是失败，而是线索——每一个修过的错误，都让你离高手更近一步。

下次遇到难题，记住这几个法宝：先拆解，再说清楚步骤，发现重复就让工具帮忙，出错时耐心排查，卡住了就把问题清楚地讲给别人听。这套思考方式不挑场合、不挑年龄，比任何一门具体的编程语言都更值钱，也更经得起时间的考验。
