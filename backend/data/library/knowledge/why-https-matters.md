# 明信片与信封

通过纯 HTTP 传输的数据像一张明信片：沿途每个路由器、每个 Wi-Fi 热点都有机会读到全部内容——你输入的密码、聊天的文字、收到的验证码一览无余。在咖啡馆的公共网络里，同网络的任何人都能截获这些明文。HTTPS 是解药：它在 HTTP 外面套上一层加密（TLS 协议），把明信片变成上锁的信封。

# 双阶段表演：先握手后密谈

难点在于双方素未谋面，怎么安全约定共同密码？HTTPS 的解法分两阶段。第一阶段用「非对称加密」完成密钥交接：网站公开一把公钥，任何人都能用它加密信息，但只有持有对应私钥的服务器解得开。浏览器用公钥加密一份随机生成的会话密钥发给服务器，全程即使被偷听，偷听者也无法还原密钥。

第二阶段改用速度快的对称加密：双方拿会话密钥对正文加解密。这样既解决了密钥配送难题（非对称），又保住了传输性能（对称）。整套流程叫 TLS 握手，发生在按下回车后的最初几十毫秒里，快到你毫无察觉。

# 小锁的第二重含义：验明正身

加密之外还有身份问题——你怎么确定对面真是那家银行而非仿冒站？答案是证书体系：网站向权威机构（证书颁发机构）申请证书，声明「这个域名归我」并由其盖章；浏览器内置了这些机构的根名单，验章通过才显示小锁图标。因此小锁有双重含义：内容已加密，且对方身份经过第三方核验。

# 加密不是万能药

最后要校准一下预期：HTTPS 保护的是「传输途中」，不等于网站本身可信。一个钓鱼网站完全可以申请到正规证书——小锁只证明「你和它之间的通信没被偷听」，不担保「它不是骗子」。同理，HTTPS 也管不住网站服务器自己泄露数据库。所以小锁是必要条件而非充分条件：没有小锁的支付页面绝对不能碰，有小锁的陌生链接照样要多留个心眼。

# 三条实用守则

守则一：涉及账号与支付，确认地址栏有小锁且域名拼写正确，形近字符（字母 o 与数字 0）是钓鱼站的惯用伎俩。守则二：遇到「证书无效」的红色警告不要强行继续访问，那可能意味着有人在冒名顶替或流量被劫持。守则三：公共 Wi-Fi 上优先使用 HTTPS 站点与官方应用，避免登录重要账号。

如今主流网站已全面 HTTPS 化，浏览器会把纯 HTTP 站点标注为「不安全」，搜索引擎也给予 HTTPS 站点更高权重。加密正在从可选项变成互联网的地基配置。

# 动手观察

分别打开一个 HTTPS 网站和一个 HTTP 网址（切记不要输入任何账号信息），对比地址栏的差异；点击小锁查看证书详情，找到颁发机构和有效期两栏。再在开发者工具的网络面板里观察一次完整请求——你会发现协议列整齐地写着 h2 或 https。看懂这些标记的那一刻，你就不再是网络世界的过客了。
