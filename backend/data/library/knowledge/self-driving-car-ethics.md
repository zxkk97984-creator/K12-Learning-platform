# 从课堂走进代码

经典电车难题：失控的电车将撞死五人，你可以扳动道岔让它只压死一人——扳吗？半个多世纪里它是哲学课的思想实验。自动驾驶的出现改变了这一切：避险算法必须在碰撞不可避免时做出真实选择，而且要提前写成代码。思想假设变成了工程必答题。

# 两套道德直觉的对撞

结果主义认为应追求最小伤害总数：救五人牺牲一人是正当的。义务论则认为主动选择伤害某人（把车转向）与被动未能施救有本质区别：不应当做「刽子手」。两套直觉在人类道德传统中长期并存、各有道理，而自动驾驶的编程必须二选一——这正是难题尖锐化的原因。

# 全球最大规模的道德调查

麻省理工学院的「道德机器」在线实验收集了二百三十三个国家和地区数千万人次的抉择数据。发现呈现共识与文化差异并存：全球普遍倾向保护人类而非动物、年轻人而非老人、更多人而非更少人；但对「是否优先保护遵守规则者」，不同文化圈差异显著。数据的价值不在给出标准答案，而在证明：不存在全人类一致的道德排序，任何写进代码的取舍都只是局部共识。

# 现实智慧的三重设计

第一重：技术压缩困境。更好的传感器、更早的风险预判、保守的车速策略——最好的避险算法是让电车根本开不进那个岔路口。第二重：程序正当性。价值排序应由公开的社会讨论和立法程序决定，而不是工程师深夜独自拍板；德国等地的自动驾驶伦理准则正是这一思路的制度化。第三重：责任先行。自动化等级划分明确每个级别下谁负责监控谁负责兜底，「有人为安全签字」这件事不能消失。

# 动手组织一次辩论

以「自动驾驶应优先保护车内乘客还是平等保护所有道路使用者」为题组织三方辩论（车企、行人团体、监管方），最后共同起草一份含三条规则的本地原则。你会发现：结论或许无法统一，但经过充分辩论得出的程序，本身就能赢得尊重——这正是处理一切科技伦理争议的通用模板。


# 写在最后

技术会不断迭代，但思考的框架是长久的。把本章的方法用到你自己的场景里试一次——无论是完成一次真实的检索、做一份小报告，还是和家人讨论一个观点。用过的知识才是真正掌握的知识，而所有的工具，最终都是为了让生活变得更清楚一点。


# 技术乐观与谨慎的平衡

自动驾驶的支持者指出一个关键事实：人类司机每年造成的事故死亡远高于 AI 司机。反对者则回应：机器犯错的方式是人类从未遇过的类型，社会还没准备好。双方都有道理——这正是为什么渐进式的路测、分级的责任划分和透明的数据公开如此重要。在乐观与谨慎之间找到节奏，是每个新技术落地的必修课。
