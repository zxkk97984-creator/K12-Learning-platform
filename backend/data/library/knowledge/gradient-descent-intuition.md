# 一场暴风雪里的任务

想象你被空投到山区，任务是抵达谷底。糟糕的是浓雾弥漫，你蒙着眼，看不见地形全貌。这几乎就是模型面对损失函数的处境：百万个参数构成起伏的「地形」，海拔是损失值，而模型每次只能感知脚下的局部坡度。梯度下降就是在这种情况下下山的方法论。

# 两个决定：方向与步长

方向问题的解法朴素到惊人：不需要看见全山，只需要知道脚下往哪边更低。数学工具「梯度」给出的正是最陡的上坡方向，反着走就是最快的下坡路。这个设计把一个全球性难题——找全山最低点——拆解成无数次局部判断：这一步往哪走？每次判断只需极少的计算量。

步长（学习率）则是艺术活。步子太小，一亿步还没走出多远；步子太大，一脚跨过谷底落到对面山坡，来回震荡甚至越荡越高直接发散。调学习率是训练模型时最常见的调试工作：太大看损失曲线爆炸，太小看进度龟速。

# 伪代码只有四行

把类比翻译回来，训练循环可以写成：「重复直到损失不再明显下降：对每个样本做预测，算出损失；计算损失对参数的梯度；更新参数——新参数等于旧参数减去学习率乘以梯度」。注意减号：梯度指向上坡，下坡要取负。现代深度学习的训练动辄百万次迭代、参数以十亿计，但骨架始终是这几行；动量、自适应步长等工程技巧都是在给这套朴素框架打补丁提速。

# 小水洼与深谷

梯度下降有个著名缺陷：它只能保证找到「某个低谷」，不保证是「最低的那个谷」。下山途中遇到小水洼——比四周都低、却远高于真正谷底的坑——站在洼地里四周全是上坡，蒙眼的人会误以为到达终点。这对应机器学习里的局部极小值问题。有趣的是，实践发现参数空间里深谷未必是好谷，不同起点落进的不同低谷性能往往相差不大，「次优解」常常已经足够好。

# 为什么不随机乱跳

有人会问：既然看不见全山，随便乱跳早晚也能碰到低处，何必讲究方向？算一笔账就明白了。参数空间里糟糕的位置占绝大多数，随机游走找到谷底的概率低得可怜；而「沿最陡下坡走」保证每一步都有确定的进展。更妙的是，实践中人们还会故意注入少量随机性帮助跳出小水洼，但主干始终是有方向的下降——先保证每步有效，再谈探索 escapes。效率来自秩序，偶尔的混乱只是调味料。

# 动手模拟

在纸上画一条波浪曲线当作山地，请同学闭眼用笔尖从随机点出发：每一步由你口头报出笔尖两侧的高度，他据此选择移动方向和距离，走二十步后展示轨迹。你会亲眼看到：起点不同终点不同；步子太大来回跳；偶尔卡在小水洼里出不来。十分钟的游戏，胜过十页讲义。
