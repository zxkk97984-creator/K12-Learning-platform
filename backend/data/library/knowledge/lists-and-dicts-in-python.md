# 先解决「往哪放」

数据分析的第一步不是计算，而是收纳。三个成绩、五十条消费记录、一整年的气温——数据得先有整齐的存放方式，后续操作才顺手。Python 准备了两件最常用的容器：列表管排队，字典管贴标签。选对容器，代码自然简洁；选错容器，处处别扭。

# 列表：按位置存取的队伍

列表用方括号按顺序存放一组值：「scores = [92, 85, 77]」。按下标取用从零开始数，「scores[0]」是第一个元素；「append」在队尾追加；「sorted」返回排好序的新副本而不动原表；切片「scores[1:3]」取出下标 1 到 2 的片段，含头不含尾——这与 range 函数的规矩一脉相承。

列表适合「顺序有意义」的数据：时间序列、操作记录、排队名单。判断标准很简单：如果你会问「第几个是多少」，就用列表。

# 字典：按名字存取的货架

字典用花括号存放键值对：「heights = {"小明": 172, "小红": 165}」，之后按名字直接取值。它适合「名字有意义」的数据：通讯录、商品价格、配置参数。键必须唯一，就像储物柜不允许两张相同的标签。

字典最强大的技能是计数汇总，这是数据分析中出现频率极高的模式，核心一行：「counts[key] = counts.get(key, 0) + 1」。遇到一个词，先取出它当前的计数（不存在给默认值零），加一再存回。把这句放进遍历循环，几行代码就能统计出词频、分类小计或去重后的种类数。「取出、加工、放回」的三步舞值得练到肌肉记忆。

# 组合拳：列表里套字典

真实数据常常是「一串带标签的记录」——比如 CSV 文件读进来的每一行。这时最自然的形态是列表套字典：外层列表管行的先后，内层字典管每行的字段名。「rows[3]["金额"]」读作「第四条记录的金额字段」，两层结构各司其职。熟练使用这种组合，是从玩具程序迈向真实数据处理的关键一步。

# 常见坑位预警

两种容器各有几个高频翻车点，提前认识能省下不少调试时间。列表的下标从零开始，「scores[len(scores)]」会越界报错，最后一个元素要用「scores[-1]」取。字典访问不存在的键会直接抛错，「counts["奶茶"]」在没有这个键时程序崩溃，安全写法是「counts.get("奶茶", 0)」。另外字典的键必须不可变：字符串、数字都可以，把列表当键则会报错。把这三个坑记在心里，写代码时就能绕开大半的报错。

# 遍历的正确姿势

两种容器各有一套优雅的遍历写法。列表直接「for s in scores:」逐个取出元素；需要下标时用「for i, s in enumerate(scores):」一次拿到位置和值。字典则用 items()：「for name, count in counts.items():」一轮拿到键和值。新手常犯的错误是遍历列表时手动维护下标、或遍历字典时先取 keys 再二次查找——这些都能用上面的写法一行解决。记住：Python 社区把「用对遍历姿势」视为代码品味的起点。

# 动手练习

建一个列表存入你最近五次测验的分数，算平均分并找出最高最低的差距；再用一个字典统计本周你购买次数最多的三种零食；最后把零食清单转成「名称对次数」的列表套字典结构并按次数排序。三道题做完，两种容器的分工就刻进手感了。
