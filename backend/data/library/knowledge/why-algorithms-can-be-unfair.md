# 一套「客观」系统的翻车

某科技公司曾开发一套 AI 招聘工具，希望它替人力资源部快速筛选简历。训练数据用的是公司过去十年的录用记录。结果系统被发现：凡是简历里出现女子学院、女性社团经历的，评分普遍被压低。项目最终被整体废弃。机器没有性别观念，它只是忠实地复制了历史数据里的不平衡。

# 偏见的三个入口

算法的不公平不是凭空冒出来的，它有三个常见入口。第一个是数据本身：训练样本覆盖不均，某类人群出现得特别少，模型就学不好他们的情况——只用城市道路图片训练的自动驾驶，进乡村可能连土路都不认识。第二个是历史惯性：过去的录用、贷款记录本身就带着偏见，模型照单全收并放大。第三个是优化目标：如果只追求「整体准确率最高」，牺牲少数群体利益往往是最省力的路径。

# 平均数会撒谎

检验公平最容易踩的坑是只看总分。一个识别系统「整体准确率高达百分之九十五」，听起来很棒；但按群体拆开统计，可能某个群体的准确率只有八成。平均数把问题藏了起来。所以负责任的团队都会做「分组体检」：把测试数据按人群、场景拆开分别打分，让差距无处藏身。

# 公平的定义也会打架

更微妙的是，「公平」本身有多种互相冲突的定义。「每个人做同样的题」是一种平等；「给起点低的人适当照顾」是另一种平等；两者在数学上常常不可兼得。招聘场景要哪种？信贷场景要哪种？这些是价值判断，技术无法替人回答。承认这一点很重要：公平不是调参数调出来的，而是先想清楚「我们要哪种公平」，再让技术去实现。

# 公平也有成本

讨论公平时别忘了一个现实问题：检验和修正偏见都要花钱花时间。分组测试需要更多标注数据，第三方审计费用不菲，为了照顾少数场景牺牲整体效率也有代价。有人因此质疑「公平的成本会不会压垮小公司」。但反过来算账：歧视性系统一旦曝光，品牌损失、法律赔偿和用户流失往往远超预防成本。公平不是慈善，而是长期主义的风险管理——这笔账，越来越多的企业开始算得清。

# 谁来当守门员

指望开发者良心发现远远不够，公平需要制度守护：开发前审查数据来源覆盖了谁、漏了谁；开发中用专门的对照样例做偏见测试；上线后持续监测，因为现实在变，昨天合格的系统今天可能走歪；重要系统还应接受第三方独立审计，就像财务报表请会计师事务所核查。作为普通用户，遇到明显离谱的结果主动投诉反馈，每一次较真都是一份免费的偏见测试数据。

# 动手想一想

如果要设计一个「自动筛选夏令营申请」的系统，哪些环节可能埋下不公平？试着至少找出三处：申请表要求填哪些信息？样本来自往届哪些学生？筛选标准偏向什么样的经历？想清楚这三问，你就已经比多数人更懂算法公平了。
