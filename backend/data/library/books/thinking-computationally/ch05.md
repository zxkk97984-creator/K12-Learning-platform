T: 步骤化：设计你的算法

S: 从想法到算法
P: 前三章的产物还停留在「想清楚了」，最后一公里是把它变成「能照着做」。把解决方案写成明确、有序、可执行的步骤序列，这个成果就叫算法，设计它的手艺叫算法设计——菜谱、导航路线、考试策略，都是生活里的算法。检验标准只有一条：一个不了解你思路的人（或机器）拿到步骤，能否准确复现结果？|mark:算法设计
@kp=flowchart-design
KC: 两个经典坑 :: 设计算法的两大坑：步骤含糊（「检查是否收齐」不算步骤）与遗漏异常分支（有人请假、写一半怎么办都要有出路）。:: 试一试 :: 找一份家电说明书，挑出含糊或缺分支的步骤。
KC: 流程图设计 :: 流程图用圆角框表示起止、方框表示动作、菱形表示判断、箭头表示流向，把算法画成一张谁都能读懂的图。:: 生活里的例子 :: 家电说明书里的故障排查图就是流程图：按菱形问题走「是/否」分支，几步定位毛病。
FIG: 一张标准的早晨出门流程图：起点圆角框「开始」，两个方框「刷牙」「吃早餐」依次相连，随后菱形「今天有体育课？」分出是/否两条路分别装跳绳与带伞，汇合后到达终点「出门」 :: 四种符号讲完所有故事：顺序走方框，选择看菱形
P: 画流程图有三个规范动作。第一，起止必须明确：从哪个状态开始、到什么条件结束，写在圆角框里。第二，判断用菱形且两条出路都要标注「是」或「否」，不留没有出口的岔路——漏标的分支就是未来卡死的地方。第三，箭头只能单向，整个图不允许出现无限绕圈的孤岛循环，除非那是刻意设计的重复结构。
CALL: 想一想 :: 自动售货机「投币→选择→出货」的流程里藏着几个菱形判断？试着至少找出两个（比如金额够不够、商品有没有货）。

S: 综合实战：四大法宝一次串联
P: 毕业任务：「设计一套班级作业收发方案」。走一遍完整流水线。第一步拆解：收作业、登记缺交、发回订正三块。第二步找规律：每天流程完全相同，只有名单变化——套用模板。第三步抽象：忽略具体是谁交了什么作业，只关心「组名、应交数、实交数」三个数字。第四步定步骤：画成流程图。
P: 画出的流程图大致如下：开始→组长收本组作业→清点数量→菱形「数量与人数相符？」→不符则对照名单找缺交者并回到收取步骤→相符则登记并交给课代表→全部小组完成后送办公室→结束。这张图贴在墙上，任何值日生无需培训就能上岗——这就是算法化的力量。
P: 流程图还有一大好处：它让讨论成为可能。口头争论常常鸡同鸭讲，但一张图摆在桌上，每个人都能指着具体的框和箭头提意见，分歧点瞬间可视化。工程师开会人手一支笔画流程图，就是这个道理。
P: 设计过程中你会踩到两个经典坑。坑一是步骤含糊：「检查作业是否收齐」不算步骤，「数一数每组的本数并和名单比对」才算。坑二是遗漏异常分支：有人请假怎么办？作业写了一半怎么办？每个异常都需要一条处理路径，否则执行者当场卡壳。好算法的标志是把意外都安排好了。
P: 动手完成你的毕业设计：选一个真实的班级事务（如值日安排、班费公示、图书借阅），完整走四步流水线——拆解清单、识别可复用的模板、抽象出关键字段、画出流程图。成品要求：一位从没参与设计的同学照图执行一次，成功率达到百分之百。
CALL: 动手挑战 :: 给你的流程图增加一个「异常处理分支」：如果某位同学连续两天缺交，流程应该走向哪里？把这个分支补画上去。

S: 全书回顾
P: 五章一座思维工厂：计算思维定义了方向，拆解把难题切成积木，模式识别认出老朋友，抽象给问题瘦身，最后流程图把一切变成可执行的方案。四大法宝环环相扣，合起来是一句朴素的话——复杂的事情想清楚，再拆成简单的步骤做出来。
P: 这套思维不会随技术过时，因为它的本质是对清晰与秩序的追求。无论你将来写不写代码，面对庞杂任务时自动展开的四步流水线，都会是你最可靠的随身装备。愿你从此遇事不慌：再大的难题，也不过是还没被拆解的积木山，而你手里已经握着拆山的工具。
