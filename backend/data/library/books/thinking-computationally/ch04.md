T: 抓重点：抽象的智慧

S: 地铁线路图的启示
P: 打开一张地铁线路图：弯弯曲曲的真实轨道被拉直成整齐的线段，站距完全不符合比例，地理方位也大幅变形——按真实地图的标准它「错得一塌糊涂」，却比任何精确地图都好用。因为它保留的只有乘车需要的信息：线路走向与换乘关系。这种主动丢弃细节、只留关键特征的做法就叫抽象。|mark:抽象
@kp=abstraction-thinking
KC: 抽象思维 :: 抽象是抓住与目标相关的关键特征、忽略无关细节的思考方式；丢什么、留什么，取决于你要解决的问题是什么。:: 生活里的例子 :: 地铁图扔掉距离和弯度，留下线路与换乘——所以乘客三秒能看懂。
FIG: 左右对照：左边一张扭曲的真实地铁轨道地理图，密密麻麻；右边是简洁的横平竖直线路图，只有颜色、站名和换乘圆点，标注「乘客需要的全部」 :: 抽象不是信息不全，而是为目标定制的信息取舍
P: 抽象的反面教材同样常见。有人背英语单词时把每个单词的所有义项、例句、词源抄成三大页笔记，笔记精美绝伦，考前却发现根本看不完——他保留了太多「也许有用」的细节。抽象思维问的问题恰恰相反：「为了通过明天的考试，哪些信息是必须留的？」其余果断舍弃。
CALL: 想一想 :: 一张学生卡上印着照片、姓名、学号、班级、图书馆条码、食堂余额。如果目标是「快速找到失主」，哪个字段最关键？如果目标是「图书管理」呢？同一张卡，两种抽象。

S: 抽象的两个方向
P: 方向一是做减法：建模时扔掉不影响结论的因素。物理课计算落体时间忽略空气阻力，地图软件计算路线把你简化成一个没有情绪的点——减法让问题变得可解。判断一个细节能不能扔，标准很明确：扔掉之后答案会变吗？不会变的就是可扔项。
P: 抽象在日常交流中也无处不在。妈妈说「放学直接回家」——她抽象掉了路上每一步的细节，只保留起点与终点；天气预报说「明天多云转晴」——气象学家抽象掉了几朵云的形状。听懂别人的抽象表达，做出自己的恰当抽象，这是沟通效率的双向保障。
P: 方向二是做归并：把一堆具体事物归纳成一个通用类别。「苹果、香蕉、橙子」归并成水果，「乘公交、骑车、走路」归并成通勤方式。归并之后，一条规则就能管住一类事物——「水果需要冷藏」不必逐个品种重复。编程里的函数、表格里的分类汇总，本质都是归并在工作。
P: 两个方向配合使用威力最大。设计班级值日表时先归并出「擦黑板组」「扫地组」等角色（做归并），再忽略每位同学的具体身高性格只排班次（做减法）——一张简洁的表就诞生了。抽象做得好，后面的步骤设计会自然变简单。
P: 动手练一次双方向抽象：为「描述一位同学的上学方式」设计一张最小信息卡。要求：别人拿到卡片就能复述他的通勤过程，但卡片上的信息不超过五项。写完与同学交换，检查对方能否只凭卡片画出行程草图——多一项算冗余，少一项算缺失。
KC: 减法与归并 :: 抽象有两个方向：做减法扔掉不影响答案的细节（如物理题忽略空气阻力），做归并把个体收进类别、让一条规则管住一类事物。:: 试一试 :: 为「描述上学方式」设计一张不超过五项的最小信息卡。
CALL: 动手挑战 :: 用不超过三十个字给「自行车」下定义，要求陌生人听完后能从一排交通工具里准确挑出它。反复删改三轮，体会每个词的去留挣扎。

S: 小结与预告
P: 回顾本章：抽象是为目标定制的取舍——做减法扔掉不影响答案的细节，做归并把个体收进类别；地铁图是最经典的教科书；抽象做得好，问题的复杂度会断崖式下降。
P: 拆解、找规律、抓重点三件分析型法宝已经集齐。但想清楚不等于说得清——怎么把脑中的方案表达成别人（或计算机）能精确执行的指令？最后一章请出收官法宝：流程图与算法设计。
