T: 读入真实世界的数据：CSV

S: 表格的通用语言
P: 打开电子表格软件另存一次文件，你会看到一个叫 CSV 的格式选项。CSV 全称逗号分隔值，用最朴素的方式存表格：每一行是一条记录，一行内的各个字段用英文逗号隔开。它没有任何花哨功能，却因此成了全世界数据交换的通用语——Excel、数据库、编程语言全都认。|mark:CSV
@kp=csv-format
KC: CSV 格式 :: CSV 是纯文本的表格格式，首行通常是列名（表头），其后每行一条记录、字段以逗号分隔；优点是通用轻量，缺点是没有类型和格式约束。:: 试一试 :: 用记事本打开任意一个 .csv 文件，观察它的表头行和数据行长什么样。
FIG: 左侧是电子表格视图：三行两列显示「日期/金额」；右侧同一份数据的纯文本原貌：「日期,金额」「周一,15」「周二,22」，中间箭头标注「另存为 CSV 后的真面目」 :: 华丽表格的素颜照：去掉格式和样式，只剩文字与逗号
P: 亲手读一个文件只需要几行代码。「import csv」请出标准库里的 csv 模块；「with open("账本.csv", encoding="utf-8") as f:」打开文件并保证用完自动关闭——encoding 参数很重要，中文数据缺了它可能读到乱码；然后「reader = csv.DictReader(f)」，这个聪明的读取器会自动把首行当表头。
P: DictReader 的妙处在于：遍历它得到的每条记录都是一个小字典，键正是表头文字。「for row in reader: print(row["金额"])」就能逐行取出金额字段。从此以后，文件里的几百条记录在你眼里就是上一章练熟的那个东西——一串待处理的字典。新知识只有「读进来」这一层，处理逻辑全是旧朋友。
CALL: 想一想 :: 为什么推荐 DictReader 而不是按下标取列？想象三个月后你回头改这段代码，或表头列顺序被人调整过——按名字取值的优势在哪里？
P: 动手环节：新建一个文本文件，输入五行自己的消费记录（日期,项目,类别,金额），另存为 UTF-8 编码的 账本.csv；写程序把它全部打印出来；再数一数一共读了多少条。跑通这一步，你就完成了从「玩具数据」到「真实数据」的关键一跃。

S: 真实数据的第一次下马威
P: 满心欢喜跑通之后，试试把其中一行的金额改成空或者写成「十五元」再运行。大概率你会看到 ValueError——float("十五元") 转换失败。这不是你的程序写错了，而是真实数据本来的样子：缺失、手误、格式五花八门。业内有句名言：数据科学家八成时间在清洗数据。
@kp=data-cleaning
KC: 数据清洗 :: 数据清洗指识别并处理缺失值、重复项、格式错乱等问题的过程，常用手段包括跳过坏行、填补默认值和统一格式。:: 试一试 :: 用「row.get("金额", "").strip()」先取出字符串并去空白，再判断是否为空。
P: 清洗策略没有标准答案，只有场景适配。记账场景里，一条金额为空的记录可以跳过但要计数——「共读入 30 条，有效 28 条，跳过 2 条」这样的报告远比静默忽略诚实；金额字段则可以用 try/except 捕获转换失败。清洗的原则是：宁可明说扔了什么，不可假装一切干净。
P: 清洗策略没有唯一正解，但有一条通用纪律：所有决定都要留下记录。跳过了几行、为什么跳、按什么规则填补——写进体检报告而不是藏在代码注释里。三个月后回看这份报告的你，会感谢今天多写了这几行打印语句。
P: 把本章代码升级成健壮版本：读取循环里对每行做三件事——去空白、尝试转浮点数、失败就记入坏行清单。最后打印一份小型体检报告：总行数、有效行数、各类问题各多少条。这份体检习惯会让你在后续所有数据分析中受益。
CALL: 动手实践 :: 给你的账本故意埋三个雷（空金额、多余空格、非数字），运行清洗版程序，验证每颗雷都被正确捕获并出现在体检报告里。

S: 小结与预告
P: 回顾本章：CSV 是表格世界的普通话，DictReader 让每行变成带名字的字典；encoding 与自动关闭是读写文件的两大细节；真实数据必有脏，清洗要留下诚实的痕迹。数据已经进屋，接下来终于到了最好玩的部分——向它提问。
