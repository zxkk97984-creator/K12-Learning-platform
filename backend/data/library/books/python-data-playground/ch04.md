T: 让数据开口说话：文本图表

S: 为什么数字不够用
P: 「餐饮 86 元、娱乐 40 元、交通 15 元」——这行结论准确无误，但听众需要逐个数字比较才能感受差距。若换成三根长短悬殊的横条，差距在三秒内直击大脑。可视化不是美化装饰，而是把「比较」这个认知任务从听众脑中搬进图形本身。|mark:可视化
P: 专业数据工作会用 matplotlib 这类绘图库生成精美图片，但本章我们反其道而行：只用 print 和字符串画图。理由有三——不依赖任何安装，任何环境都能跑；每个像素都是你亲手拼出来的，图形原理一览无余；文本图在聊天窗口和代码注释里随贴随用。
@kp=iteration-aggregation
KC: 文本条形图 :: 用重复的实心字符（如 █）按数量比例排成横条，一行一个类别，是纯文本环境下最直观的对比图形式。:: 试一试 :: 运行「print("█" * 10)」和「print("█" * 3)」，直观比较两条「柱子」的长短。
FIG: 终端窗口截图风格：五行输出依次为「餐饮 ██████████████████ 86」「娱乐 █████████ 40」「文具 █████ 24」「交通 ███ 15」「其他 ██ 9」，右侧标注「1 格 = 5 元」 :: 同一份聚合结果的三秒读懂版：条形长度替听众完成了所有比较
P: 核心技巧只有一行：「print("█" * n)」——字符串乘整数就是自我重复。把它装进遍历字典的循环，「for name, total in counts.items():」每轮打印类别名、按金额生成的条、再附上原始数值，一个完整的横向条形图就诞生了。上一章的漏斗，这一章接上出水口。
CALL: 想一想 :: 如果某类花了 300 元而最少的只花 3 元，直接一格代表一元会发生什么？提示：想想终端屏幕的宽度和「比例缩放」这个词。

S: 缩放与诚实
P: 大数字必须缩放，否则图会撑爆屏幕。做法是先定比例尺：算出最大值，规定最长条占四十格，其余条长等于「金额除以最大值乘四十」取整。「int(total / max_total * 40)」一行搞定。缩放后每根条的相对长短不变，绝对格数却都装得下了——这正是所有专业图表「坐标轴刻度」的本质。
P: 但缩放带来一个伦理细节：看图的人不知道比例尺，可能误读。所以务必在图旁标注「1 格 = X 元」或直接保留原始数字列。第四章数据侦探的教训在此回响：图形的力量越大，误导的责任越重。诚实的图永远自带说明。
P: 图表的价值在沟通中才兑现。同样的数据，给同学看要突出对比，给家长看要突出趋势，给自己看要突出异常。先想清楚观众是谁、他们关心什么，再决定画什么图、标什么数字。这份观众意识，是把代码输出升级为数据沟通的分水岭。
P: 再进阶一步：给图加排序与装饰。先用 sorted 把类别按金额降序排列再画图，视线扫过就是一条从高到低的滑梯；条尾补齐空格对齐数字列，整体立刻工整。这些小打磨不影响正确性，却大幅提升可读性——沟通意识正是从这类细节开始生长的。
KC: 比例尺缩放 :: 画图前先按最大值把所有条形等比压缩到可用宽度内，相对长短不变、绝对长度可控，并务必标注换算关系防止误读。:: 试一试 :: 把 300 与 3 元的两根柱子都压进四十格宽度。
CALL: 动手挑战 :: 给条形图增加一个「超支警戒线"：日均预算对应的格数位置统一插入一个「│」标记，超预算的类别一眼可见。动手实现它。

S: 小结与预告
P: 回顾本章：可视化的本质是把比较搬进图形；字符串乘法是最小的画笔，循环加字典是画架；缩放解决大数问题，标注守住诚实底线；排序与对齐是沟通意识的起点。
