T: 数据的容器：列表与字典

S: 先解决「往哪放」的问题
P: 数据分析的第一步不是计算，而是收纳。三个成绩、五十条消费记录、一整年的气温——数据得先有个整齐的存放方式，后续操作才顺手。Python 准备了两件趁手容器：列表管排队，字典管贴标签。本章把这两件玩熟，全书的地基就打好了。|mark:容器
@kp=list-container
KC: 列表容器 :: 列表用方括号按顺序存放一组值，支持按下标取用、追加元素和整体遍历，是同类型数据的默认选择。:: 试一试 :: 输入 scores = [92, 85, 77]，再试 print(scores[0]) 和 print(sum(scores))，观察输出。
FIG: 两格储物架对比图：左架是一排带编号的格子（0、1、2……）标着「列表·按位置取」，右架是贴满名字标签的抽屉柜标着「字典·按名字取」，一只手分别从编号格和标签抽屉里取物 :: 两种取货方式：知道位置就用列表，知道名字就用字典
P: 列表的常用动作很快就能上手：「scores.append(88)」在队尾加一个新数；「len(scores)」数有几个；「sorted(scores)」返回一份排好序的新列表而不动原列表。切片语法「scores[1:3]」取出下标 1 到 2 的片段，含头不含尾——和上一本书里 range 的规矩一脉相承。
P: 但有些数据天然不适合排队。比如全班同学的身高对应姓名，「谁多高」比「第几个多高」重要得多，这时该请出字典。「heights = {"小明": 172, "小红": 165}」之后，「heights["小明"]」直接按名字取值。花括号书写，冒号左边是键右边是值，键必须是唯一的。
CALL: 想一想 :: 一份通讯录（按名字查电话）和一段跑步配速记录（按时间先后排列），各自适合用哪种容器？说出判断依据。

S: 字典的看家本领
P: 字典最强大的技能是「计数汇总」，这是数据分析中出现频率极高的模式。核心只有一句：「counts[word] = counts.get(word, 0) + 1」——遇到一个词，先用 get 取出它当前的计数（不存在就给默认值 0），再加一存回。把这句放进「for word in words:」的循环里，跑完就能得到每种词的出现次数。
P: 逐动作拆开看：假设词表是 ["苹果", "香蕉", "苹果", "梨"]，循环第一轮 get("苹果", 0) 得 0 加一存回；第二轮再遇到苹果，取出的已是 1，加一变 2。四行代码跑完，counts 变成 {"苹果": 2, "香蕉": 1, "梨": 1}。「取出、加工、放回」的三步舞你在编程入门书里见过数字版，如今它开始处理真正的业务了。
@kp=iteration-aggregation
KC: 迭代聚合 :: 迭代聚合指用循环遍历每条记录，逐条累加数值或累加计数，最终得到总量或频次分布的处理模式。:: 试一试 :: 把上面四行代码里的词表换成一周七天的零花钱数额，统计总支出。
P: 遍历字典用 items()：「for name, count in counts.items():」一次拿到键和值，配合 f 字符串「print(f"{name}: {count} 次")」就能输出漂亮的清单。到这里你已经具备做小型汇总报表的全部语法基础——剩下的只是把真实数据喂进来。
P: 两种容器还能组队作战。真实的数据常常是一串带标签的记录，最自然的形态就是列表里套字典：外层列表管行的先后，内层字典管每行的字段。「rows[3]["金额"]」读作第四条记录的金额字段。两层结构各司其职，这是从玩具程序迈向真实数据处理的关键一步。
P: 动手练习：建一个列表存入你最近五次的测验分数；算出平均分并打印；找出最高分和最低分的差距；再用字典统计五种零食在你本周购买记录中各出现几次。做完这组练习，下一章的真实文件对你来说只差一步「读进来」而已。
CALL: 动手挑战 :: 只用一行 print，把 scores 列表变成「92 → 85 → 77」这样的箭头串输出。提示：回忆字符串的 join 方法需要的是字符串序列。

S: 小结与预告
P: 回顾本章：列表按位置存队列，字典按名字存货架；切片含头不含尾；get 加一的计数模式是数据分析的第一块积木。容器备齐，可它们现在还只能装手打的死数据。
P: 真实世界的数据躺在文件里：账本导出成表格、学校发来的名单、运动手环的记录。下一章学习读取最常见的表格格式 CSV，让你的程序第一次吃上「活数据」。
