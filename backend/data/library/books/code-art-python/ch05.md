T: 创意项目：我的数字花园

S: 从草图到代码
P: 毕业创作日。任务：完成一幅「数字花园」——画面里至少包含天空背景、三朵以上不同形态的花、一个太阳或月亮，并签上你第一章设计的字母签名。老规矩，先纸面设计后动手：把画面分成几块区域？每块放什么元素？主色调选什么？十分钟的设计稿能省半小时的返工。|mark:数字花园
P: 设计示范：上半屏浅蓝天空加右上角橙红太阳；下半屏绿草地；草地上一排三朵花——左边红色八角曼陀罗、中间黄色实心圆加花瓣、右边紫色五瓣弧线花；右下角白色签名。布局遵循「主体居中偏上、装饰靠边」的构图常识，避免元素挤成一团。
FIG: 一幅完成的花园截图：浅蓝天空、橙色半圆太阳悬在右上，绿色地平线，三朵形态各异的花错落排开，右下角一行白色字母签名 :: 一座用十几段循环种出来的花园：每个元素都是旧知识的组合

S: 模块化：把每朵花变成函数
P: 直接从头写到尾会让代码乱成一团。聪明做法是模块化：每种花写成一个函数。「def draw_flower(color, petals):」定义好一朵可参数化的花，之后每次调用只需改颜色和瓣数。位置管理统一用抬笔跳转：画完一个元素，抬笔飞到下一个坐标。

KC: 模块化绘制 :: 把每种图形封装成带参数的函数（如指定颜色与瓣数的花），调用时传不同参数即可批量生产变体，是组合复杂画面的核心技巧。:: 试一试 :: 定义一个「画星星」函数，用不同颜色和大小调用三次。
KC: 先设计后编码 :: 动笔前先用纸面草稿确定布局、元素与配色，五分钟的设计省掉半小时返工；每完成一个模块立即运行确认，小步快跑。:: 试一试 :: 为最终作品先画一张分区草图。
P: 调试画面类程序有个独家秘诀：给每段代码加上临时的不同颜色。如果某个元素没出现，把它改成亮红色再运行一次——是根本没执行到，还是被别的元素盖住了？颜色会替你说话。定位完成后记得改回正式配色。
P: 写作顺序有讲究：先画背景（天空矩形加地面矩形），再画远处的太阳，然后从后往前画花——后画的会盖住先画的，这个遮挡规则和画画一样。最后签名收尾。每完成一个模块就运行一次确认无误，别攒到最后一次性调试——小步快跑是所有创作者的保命符。

S: 展示与迭代
P: 作品完成后进入展评环节。给家人或同学演示时，别只放最终图——现场改两个参数重新运行：把太阳换成月亮色、花瓣翻倍、换一套配色，让观者亲眼看到「改代码即改画面」的魔法瞬间。这比静态图片震撼十倍，也最能体现生成艺术的本质：作品不是一张图，而是一台造图机器。
P: 作品完成后别忘了导出保存：绘图窗口保持打开时直接截图即可，给文件起个有意义的名字加上日期，比如「花园第二版五月二十一日」。重要成果永远至少存两个地方，未来的你会感谢现在的整理习惯。
P: 迭代方向送你三个。其一，加入随机性：「import random」让花瓣数量或位置每次微变，花园从此独一无二。其二，加入动画：让太阳缓缓移动（简单循环加小步刷新）。其三，交互：点击屏幕某处就在那里种一朵花。任选其一实现，你的作品就超越了本教程。
P: 全书回顾：一只小海龟带你走完了直线、循环、色彩、圆弧四站，最终把几段循环组装成一座花园。回头看第一章那三行代码的三行横线，再看看今天的作品——中间隔着的不是天赋，而是五次「学会一招就用一招」的积累。
P: 展示时还可以讲讲创作故事：哪个参数调了最久？哪次失败反而带来了惊喜？听众最爱听的就是这些转折。会讲作品的程序员，和只会交作业的学生，走的将是两条路。
P: 编程与艺术在这里握手：代码是新的画笔，屏幕是无尽的画布。愿你保持这种「用代码造东西」的快乐，它会在未来某个时刻，突然为你打开一扇意想不到的门。
