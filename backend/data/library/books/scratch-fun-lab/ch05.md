T: 小项目：接苹果游戏

S: 开工：先当导演再拼积木
P: 大项目开工前，导演要先想好剧本。我们的游戏规则是：苹果从天上慢慢落下，玩家用左右键移动一只碗去接；接住加一分，苹果落地就消失重来。想清楚再动手，是程序员和普通玩家的最大区别。把剧本拆成三个角色的任务清单，每个角色领自己的活儿。|mark:任务清单
P: 苹果的任务：从顶上随机位置出现，不停往下掉，掉到底部回到顶上。碗的任务：听左右键指挥左右移动，碰到苹果就加分。舞台的任务：亮出记分牌。看，一句话的愿望变成了三份清楚的工作单——这就是第四章说的顺序执行思路在项目管理上的用法。
CALL: 想一想 :: 为什么要把任务先分给角色，而不是想到哪块积木拼哪块？如果直接开拼，你猜会在哪里卡住？

S: 苹果和碗的脚本
P: 先给苹果写脚本：绿旗开关下面，把初始 y 坐标设为 180（天顶），x 坐标设为「在 -240 到 240 间随机选一个数」——绿色分类里就有这块随机积木，它让每次出现的地点都不一样。然后进入重复执行口袋：y 坐标每次减少 5（往下掉），如果碰到边缘就回到顶部重新随机一个 x。
@kp=score-variable
KC: 计分变量 :: 计分变量像一个电子记分牌：接住苹果时加一，舞台上立刻显示新分数。变量让程序拥有了会变化的记忆。:: 试一试 :: 新建变量「得分」，在接到苹果的那一刻用「将得分增加 1」，分数就会自己涨。
KC: 广播消息 :: 广播消息是角色之间的传声筒：一个角色喊一声「接到啦」，所有竖着耳朵听这个消息的角色同时行动。:: 生活里的例子 :: 上课铃一响，全校同学同时回教室——铃声就是一条广播消息。
P: 再给碗写脚本：绿旗开关、重复执行口袋、两个如果积木——按右键 x 增加 10，按左键 x 减少 10。最后装上心脏部件：「如果 碰到 苹果？那么 将得分增加 1，并广播一条消息叫苹果回顶」。变量在哪建？橙色分类里点「建立一个变量」，起名「得分」，舞台角落自动出现记分牌。
FIG: 游戏画面示意图：舞台上方一个红苹果正在下落，下方一只碗张口等待，左上角记分牌显示「得分 7」，旁边配着两段简短积木脚本的缩略图 :: 一个完整的小游戏：下落的苹果、听话的碗、会跳动的分数
P: 两个角色各忙各的还不够，得让它们打招呼。碗接到苹果时用「广播 接到啦」喊一声，苹果的脚本开头放上「当接到 接到啦」，听到消息就跳回顶上重新掉落。角色之间这样传纸条，配合就默契了。
P: 点绿旗试玩！苹果摇摇晃晃落下来，你操纵碗稳稳接住，记分牌跳成 1、2、3……如果一切正常，恭喜你正式成为游戏制作人。如果有积木不听话，回头逐块检查：开关放了吗？口袋锁紧了吗？六边形缺口填了吗？排错的过程本身就是最好的练习。
P: 玩几局你可能觉得太简单？给游戏加点难度：新建变量「速度」，每得五分就让苹果每轮多掉 1。还可以加个倒计时六十秒，时间一到用广播消息通知全场「游戏结束」。这些升级全是你学过的老朋友：变量、如果、广播。
CALL: 动手创造 :: 给游戏加上你的专属创意：换一个角色？接住时播放欢呼？连击三次出现彩蛋台词？记住，你的游戏你做主。

S: 全书回顾
P: 五章下来，你从认识舞台出发，学会了让角色运动、说话、发声，掌握了如果和重复两大神器，最后独立完成了一个能计分的游戏。回头看第一章那个只会走一步的小猫，是不是恍如隔世？
P: 更宝贵的是你悄悄学会的思考方式：把大目标拆成小任务，把任务翻译成一步步的指令，出了问题一块块排查。这套本事不只属于编程，写作文列提纲、准备运动会方案，用的都是它。保持动手，保持好奇，实验室永远为你开放。
