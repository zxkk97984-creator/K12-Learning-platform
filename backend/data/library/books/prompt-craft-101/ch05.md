T: 迭代改进与常见陷阱

S: 首轮回答只是起点
P: 高手与新手最大的差异不在首轮提示词，而在之后的操作。新手看到不满意的回答就放弃：「AI 也就这样。」高手则把首轮当草稿，开始精准追问：「第二点展开讲讲，其余删掉。」「语气太正式了，改成同学之间聊天的感觉。」「举一个校园里的例子。」两三轮之后，结果脱胎换骨。这套功夫就叫迭代改进。|mark:迭代改进
@kp=prompt-iteration
KC: 迭代改进 :: 迭代改进指把 AI 的首次回答当作草稿，用具体的反馈多轮追问修改，每一轮只聚焦一处调整，逐步逼近理想结果。:: 生活里的例子 :: 理发师不会一次剪到位，先剪一刀看看再修——好发型是聊出来的，不是喊出来的。
FIG: 一个螺旋上升的阶梯图：第一级「初稿」经三段反馈箭头（「第二点展开」「语气放松些」「加个例子」）逐级抬升到「定稿」，每级台阶旁标注一轮对话 :: 好结果是磨出来的：每轮反馈只改一件事，台阶才爬得稳
P: 有效反馈的关键词是具体。「写得好一点」是无效指令——好没有标准；「把开头改成疑问句，制造悬念」才是可执行的修改。一次只提一类修改也是纪律：同时改结构、语气和例子，模型容易顾此失彼，逐项推进反而更快收敛。
CALL: 想一想 :: 为什么「一次只改一处」在人与人的合作里同样有效？回想一次小组作业中因意见堆叠而返工的经历。

S: 陷阱一：诱导性提问
P: 有些问法天生把对话带向沟里。「为什么吃冰激凌会导致溺水？」——问题预设了假因果，模型往往顺着框架一本正经地编理由。「既然所有天鹅都是白的，黑天鹅去哪了？」同理。这类诱导性提问利用的是模型「顺着用户说」的倾向：你搭好错误的舞台，它就会演错误的戏。|mark:诱导性提问
@kp=leading-question-trap
KC: 诱导性提问陷阱 :: 诱导性提问在问题里预设了未经证实的前提，模型倾向顺着前提作答而非先纠正它，从而生成貌似合理的错误内容。:: 试一试 :: 把「为什么天是圆的」发给 AI，观察它是否先纠正「天并不是圆的」。
P: 防御方法是把「为什么」换成「是否」。不确定因果时先问：「吃冰激凌和溺水有关系吗？关系背后的原因是什么？」给模型留出否定前提的空间。另一个习惯是主动要求批判：「请指出我上面这个说法可能存在的错误。」邀请反驳的提问者，最不容易被带偏。

S: 陷阱二与陷阱三
P: 第二个陷阱是把 AI 当权威数据源。让它列举「某某领域的十大里程碑事件」，它可能流畅地列出几条根本不存在或年份张冠李戴的条目。涉及事实清单、引用出处、精确数字的内容，必须逐条核实——提示词技巧再高也改变不了模型的这一本性。
P: 第三个陷阱是过度信任长答案。篇幅长、结构美、语气笃定，都不代表内容可靠；恰恰是这类输出最容易让人放下戒心。对策是养成「格式免疫」：评估回答时只问三个问题——事实有据吗？推理成立吗？来源可查吗？与排版华丽与否无关。
P: 动手做一次完整的实战演练：选一个你真实需要的小任务（比如整理一份复习要点），走完全流程——四要素加角色写出首版提示词；不满意处逐轮追问打磨；最后人工核实全部事实性内容。把五轮对话记录保存下来，这就是你的第一份提示词作品集。
CALL: 动手演练 :: 设计三条诱导性提问（含错误前提），检验你使用的模型是否会被带偏；若被带偏，追加一句「请先检查我的问题是否成立」，观察它的反应。

S: 全书回顾
P: 五章一条完整的成长线：从理解输入决定输出，到用四要素搭骨架、用角色设定调风格、用少样本示例锁格式，最后靠迭代改进打磨成品并避开三大陷阱。这套方法论的本质只有一句话——把对人类沟通的要求原样应用到机器身上。
P: 提示词技巧会随模型进化而部分失效，但「把任务想清楚再开口」的能力永不贬值。愿你从今天起，做一个提问有结构、追问有耐心、核实成习惯的智能时代使用者。
