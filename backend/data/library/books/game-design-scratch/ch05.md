T: 小小游戏测试员

S: 设计师的最后一关
P: 你觉得自己做得挺好？真正的考验现在才开始：把游戏交给别人玩。职业游戏公司在发售前都要请大量玩家试玩，这个环节叫游戏测试。原因很简单：设计师太熟悉自己的作品了，哪里有星星、机关在哪全都背下来了——而新玩家看到的才是真实的第一印象。|mark:游戏测试
@kp=playtesting
KC: 游戏测试 :: 游戏测试指请目标玩家试玩作品并观察记录他们的反应，用真实反馈发现问题、指导修改；好游戏都是测试改出来的。:: 生活里的例子 :: 新菜上市前厨师总要请人试吃——咸淡只有吃的人知道。
KC: 意见与方案 :: 玩家说「太难了」是意见，说「应该把星星变大」只是方案；设计师要抓住意见本身，从多个方案里找真正的解法。:: 试一试 :: 把一条玩家意见翻译成两种不同的修改方案。
P: 测试前准备三样东西：一台打开游戏的电脑、一支笔和一张记录表。记录表分两列：「玩家做了什么」和「玩家说了什么」。测试时管住自己的嘴——不要教玩法、不要解释设计意图，只在旁边安静观察。玩家卡住了、皱眉了、笑出声了，统统记下来，这些瞬间就是最珍贵的情报。
FIG: 一张测试现场插画：一位同学在玩平板游戏，旁边的设计师拿着纸笔认真记录，头顶三个气泡分别写着「他卡在这里」「他笑了」「他说想跳过」 :: 安静地看，认真地记——玩家的每个表情都是改进线索

S: 收集意见的正确姿势
P: 玩家试玩后要问四个标准问题：哪里最好玩？哪里最难受？你明白怎么玩吗？还想再玩一次吗？前两个找优点和痛点，第三个检验规则是否讲清楚了，第四个是衡量好玩程度的终极指标——真心想再玩的游戏才站得住脚。
P: 收集意见时还有一条重要纪律：分辨「意见」和「方案」。玩家说「太难了」是宝贵意见，但玩家说「应该把星星变大」只是他的一个方案——也许把飞船变大更容易解决。设计师的工作是从众多方案里找到问题的真正解法，照单全收反而会把游戏改成大杂烩。
CALL: 动手实践 :: 请两位同学分别试玩五分钟并完成四问访谈，把回答逐条写进记录表，标出被两个人都提到的意见——重复出现的意见优先处理。

S: 从反馈到更新
P: 拿到反馈后按影响排序修改。常见问题对应经典药方：太难了就降低星星下落速度或增加生命；太简单就加快速度或减少生命；不知道怎么玩就在开头加一页操作说明；玩两次就腻就增加难度递增——每得十分星星加速一点。
P: 改完不是终点，还要再测一轮验证改动是否生效。设计、测试、修改、再测试——这个循环转得越多轮，作品就越接近「好玩」。职业游戏从立项到发售平均要经历几十轮测试，你的三轮五轮只是伟大征程的开始。
P: 全书回顾：第一章认清三样宝贝，第二章纸上设计关卡，第三章装上心跳般的输赢系统，第四章完成视听包装，第五章用真人测试打磨成品。你已经走完了独立做出一款完整游戏的全流程——这不是玩具作业，这是货真价实的作品。
P: 把你的游戏分享出去吧！Scratch 社区里有千万玩家等着试玩你的创意。看到陌生人在你的世界里快乐地挣扎，你会理解设计师这个身份的全部荣光——理解了它，后面的学习会顺畅许多。。
CALL: 下一步去哪儿 :: 设计师之路刚刚开始 · 可以挑战给游戏加关卡选择菜单，或者尝试设计一款完全不同类型的解谜游戏。下一本书见！
P: 设计师笔记 · 本章做的东西里，最让你有成就感的是哪一步？把它记在笔记本上——下次卡住的时候翻回来看，你会发现原来自己已经走了这么远。这种记录进步的习惯，比任何技巧都更能支撑你走完创作全程。
P: 分享前还有一个法律小贴士：Scratch 社区要求作品标注「基于他人修改」还是「原创」。如果你的游戏借鉴了别人的素材（比如音效库或角色造型），记得在说明里注明来源——尊重创作者的劳动是设计社区的基本礼仪，也是你未来走向专业世界的通行证。
