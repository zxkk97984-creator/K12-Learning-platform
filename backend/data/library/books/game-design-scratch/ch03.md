T: 加上生命和输赢

S: 让星星落下来
P: 先完成星星的下落。给星星写脚本：绿旗点击后移到顶部随机位置，「重复执行」里让 y 坐标每次减少五——星星开始缓缓下落。再复制几个星星角色（右键角色区选复制），天上就有了一群星星。运行试试，接住它们！——这个机制就叫生命值。|mark:生命
P: 现在的游戏有个大问题：永远不会输。没有失败风险的游戏就像没有守门员的足球赛，一点不紧张。解决方案是给玩家有限的犯错机会——这就是生命条的由来。新建一个变量叫「生命」，初始值设为 3；每漏掉一颗星星减 1；生命等于零时游戏结束。
@kp=life-counter
KC: 生命计数 :: 生命计数用变量记录玩家剩余的犯错机会：每失误一次减一，归零时游戏结束。它把「可以无限重来」变成「每一局都珍贵」。:: 生活里的例子 :: 街机游戏机台上的三个币，投完就得回家——有限才让人珍惜。
FIG: 舞台左上角显示三颗红心图标标着「生命 3」，一颗星星落地瞬间红心少了一颗变成「生命 2」，旁边配一个向下的箭头和感叹号 :: 三颗红心就是三次机会：每一次失误都看得见代价
P: 输的条件写好了，赢的条件也要有。「太空接星星」可以这样设计：得分达到三十分就算胜利，播放庆祝音效并显示「你赢了！」大字。用一块如果积木判断「得分大于或等于三十」，成立时广播一条「胜利」消息，舞台背景切换成庆祝画面——这就是输赢条件。
CALL: 想一想 :: 为什么游戏要同时设计「怎么赢」和「怎么输」？只有一个结局的游戏（永远赢或永远输）还能叫游戏吗？

S: 广播：让所有角色一起行动
P: 游戏结束时，很多角色要一起行动：星星停止下落、飞船定格、屏幕显示结果。逐个通知太麻烦，Scratch 的广播功能一句话搞定全队。发送方用「广播 游戏结束」，接收方们各自写一段「当接收到游戏结束」的脚本：星星停住、飞船隐藏、舞台切换。一声哨响全场行动，这就是广播的作用。
@kp=win-lose-condition
KC: 输赢条件 :: 输赢条件是明确的胜负判定规则：分数达标判胜、生命归零判负，通常配合广播消息让全部角色同步进入结算状态。:: 试一试 :: 得分达到三十时广播「胜利」，让舞台切换成庆祝画面。
P: 动手把输赢系统装进你的游戏：新建生命变量并设初值为三；星星触底时将生命减一并回到顶部重新落下；生命小于一时广播「游戏结束」。再加胜利判定：得分达到三十广播「胜利」。测试两个结局都能正确触发——能赢也能输的游戏，才有了心跳。
CALL: 动手挑战 :: 给游戏加一个「重新开始」按钮角色：点击它时把生命设回三、得分清零、广播「重新开始」。想想哪些角色的脚本需要响应这条新消息。

P: 设计师笔记 · 本章做的东西里，最让你有成就感的是哪一步？把它记在笔记本上——下次卡住的时候翻回来看，你会发现原来自己已经走了这么远。这种记录进步的习惯，比任何技巧都更能支撑你走完创作全程。
P: 输赢判定还有一个细节值得打磨：结束的瞬间不要太突兀。加一个短暂的慢动作或画面渐暗，让玩家有时间消化结果——「刚才差一点就赢了」的遗憾感恰恰是再玩一次的动力来源。节奏感是看不见但摸得着的设计功力。

S: 小结与预告
P: 回顾本章：星星靠重复执行加坐标递减实现下落；生命条用变量记录犯错机会，归零即失败；胜利条件配合广播让全体角色同步结算；能赢会输的游戏才有紧张感。
P: 现在你的游戏已经完整可玩了！但它还差最后一层包装：接住星星时没有爽快的反馈，背景音乐也没有。下一章我们用音效和动画给游戏注入灵魂。
