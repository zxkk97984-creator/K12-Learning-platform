T: 黑箱里的决定：透明与解释

S: 说不清理由的裁判
P: 想象一位老师宣布你的成绩不合格，却拒绝说明原因，只说「我就是这么判断的」。你一定觉得荒唐。可现实中许多 AI 系统正是这样的裁判：贷款申请被拒、简历没过初筛、视频被下架，用户只收到一个结果，看不到任何理由。这类内部过程难以被人读懂的模型，被称为黑箱。
@kp=black-box-problem
KC: 黑箱问题 :: 黑箱问题指深度模型的内部判断路径由数亿个数字参数共同构成，人类难以将其翻译成能理解的语言，只能观察输入和输出。:: 生活里的例子 :: 像一个味觉惊人的厨师，菜做得极好却说不出放了哪些调料、各放多少。
FIG: 左侧一个不透黑的箱子：输入「简历」从上面进入，侧面输出「不合格」，箱子表面画满问号；右侧同一只箱子被打开一条缝，露出层层齿轮和一张便签写着「部分可解释工具」 :: 黑箱不是魔法，是还没找到合适的翻译方式——研究者正在撬开这条缝
P: 为什么会这样？回忆机器学习的原理：模型是从数据中自动调出几百万个参数权重，而不是按人写好的规则运行。规则系统的每一步都能念给人听；神经网络的优势恰恰在于自己发现人想不到的模式——代价是那些模式散落在海量数字里，没有现成的人类语言对应物。
CALL: 想一想 :: 「模型说不出完整理由」和「模型根本没有理由」是一回事吗？人凭直觉做出判断后，也常常说不清完整依据——这算黑箱吗？

S: 我们有权知道理由吗
P: 先看一个对照场景：司机闯红灯被抓拍，罚单上写明时间地点依据条款；而算法拒了你的申请，却可能连一句解释都没有。两相对比就能感到失衡。当算法越来越多参与升学推荐、信用评估、内容分发这些影响命运的决定，「有权得到解释」正在成为新的基本诉求。
P: 完全的透明既做不到也没必要——公开全部参数等于公开作弊手册，还可能泄露他人隐私。现实的平衡点是「有意义的解释」：告诉被决定者主要影响因素是什么（例如「负债比例过高」而非「综合评分 3.7」），提供申诉渠道，允许人工复核。让解释服务于监督，而不是炫技。
P: 有一个类比能帮你向家人解释黑箱。一位老医生凭几十年经验一眼判断病情，你说不清他脑中哪些神经在放电，但可以问他的诊断思路、请另一位医生复核——解释不必深入到神经元，只要足以让人检验和质疑即可。模型同理：我们追求的是决策层面的可追问，而不是电路层面的透明。
P: 技术界也在认真回应。可解释人工智能是一个活跃的研究方向：有的工具能指出模型看图时关注了哪些区域，有的能给出每个因素的贡献度排序，还有团队干脆为高风险场景选用天生好解释的简单模型。趋势很清晰：越是影响重大的场合，越要把可解释性当作硬指标而不是加分项。
P: 对你我而言，实用策略有三条：重要决定要求人工复核，这是很多地区赋予的权利；对「系统就是这么判的」的说法敢于追问；养成查证习惯，不让任何单一信息源定义你是谁。黑箱时代，追问本身就是一种力量。
KC: 有意义解释 :: 有意义的解释指告诉被决定者主要影响因素并提供申诉复核渠道，而不是公开全部参数，更不是一句「系统就是这么判的」。:: 试一试 :: 把「综合评分不足」改写成一条你能据此改进的具体理由。
CALL: 动手设计 :: 给学校设想中的「作业智能批改系统"写一份解释义务清单：它至少应该向学生、向老师分别解释什么？

S: 小结与预告
P: 回顾本章：黑箱源于模型自我发现的模式缺乏人类语言对应物；完全透明不可能也不必要，有意义解释加人工复核才是可行解；可解释性正从研究课题变成硬性要求；作为用户，追问与申诉是普通人的正当武器。
P: 就算解释到位、天平摆正，仍剩最后一个尖锐问题：如果系统确实造成了伤害，谁来赔？开发者说「我只是写了代码」，使用方说「是 AI 判的」——下一章我们来拆这道责任难题。
