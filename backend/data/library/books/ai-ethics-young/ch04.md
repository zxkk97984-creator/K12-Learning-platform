T: 出了错谁来负责

S: 一起小事故引发的追问
P: 设想一个真实感十足的场景：某外卖平台的调度 AI 把订单派给了一位账号被冒用的骑手，餐送丢了，顾客投诉，平台客服回复：「这是系统自动分配的，我们也没办法。」这句话里藏着一个巨大的伦理漏洞——如果「系统干的」能成为挡箭牌，那以后所有错误都可以没有主人。
@kp=accountability-chain
KC: 责任链 :: 责任链指从数据提供、模型开发、测试验收到部署运营的每个环节都登记明确的责任主体，事故发生后可以逐环节追溯。:: 生活里的例子 :: 食品出问题能追到具体厂家和批次，靠的是全程记录的追溯体系。
FIG: 一条四环相扣的铁链：每环分别标着「数据」「开发」「测试」「运营」，一只放大镜沿链检查，最末端的「运营」环上挂着一块写有「最终责任：使用方」的牌子 :: 链条任何一环断裂都会出事，但对外负责的始终是拿着产品的最后一环
P: 为什么责任要拆成链条？因为一个 AI 系统是几十上百人协作的产物：数据标注员、算法工程师、测试团队、决定上线的管理层、日常运营方。笼统地问「谁的错」只会互相甩锅；逐环节追问——数据有没有问题？测试覆盖了吗？上线决策谁签的字？——才能定位真正该改进的地方。
P: 但链条再细，也必须有一个最终兜底者，那就是把系统投入使用并从中获利的机构。这和汽车行业的逻辑一致：刹车失灵可以追查零件供应商的责任，但车主面对的是整车厂。让使用者对用户负总责，倒逼他们替你把关每一个上游环节。「系统自动的」在法律和伦理上都越来越站不住脚。
CALL: 想一想 :: 如果规定「AI 参与的决定必须有人签字背书」，签字的人会变得更谨慎吗？这会不会拖慢效率？谨慎与效率该怎么平衡？

S: 新兴的行业规矩
P: 世界各地正在把这些共识变成硬约束。欧盟人工智能法案按风险给 AI 分级，医疗、招聘等高风险应用需要满足严格义务；我国出台的算法推荐管理规定要求平台备案算法、提供关闭选项；多个行业标准引入了「AI 影响评估」，上线前先评估可能伤害哪些人群。
P: 对个人从业者，行业也开始推行类似医生誓言的伦理承诺：拒绝参与明显有害的项目，发现问题产品敢于内部吹哨。这些听起来遥远，其实和你有关——今天你在课堂上讨论「该不该帮朋友写作弊程序」时的判断力，就是未来工程师面对压力时的底气来源。
KC: 最终兜底原则 :: 无论内部环节多复杂，把 AI 系统投入使用并从中获利的机构必须对用户负总责，这是倒逼它把关上游的动力机制。:: 试一试 :: 复盘任何一次产品事故，试着找出链条上「最终签字」的那一环。
P: 把视角拉回你自己。作为用户，你也在责任链上：不滥用工具伤害他人、发现缺陷积极反馈、转发可疑内容前先核实。一个健康的 AI 生态，从来不是只靠立法者和公司维护的，它由千万个较真的普通用户共同托底。
CALL: 动手演练 :: 复盘本章开头的外卖事故：请写出责任链四个环节各自可能的问题点，以及「最终兜底方」应该向顾客做出的补救。

S: 小结与预告
P: 回顾本章：「系统自动的」不是免罪金牌；责任链让每个环节可追溯，而使用机构负最终责任；法规分级监管、行业伦理承诺、用户反馈共同织成安全网。公平、透明、责任三块基石已经就位，还差最后一块——也是最贴身的一块：隐私。
