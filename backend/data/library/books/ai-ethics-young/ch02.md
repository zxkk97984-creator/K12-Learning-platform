T: 公平这把尺子：算法会偏心吗

S: 一套「客观」系统翻车记
P: 某科技公司曾开发一套 AI 招聘工具，希望它替人力资源部快速筛选简历。训练数据用的是公司过去十年的录用记录。结果系统上线后被发现：凡是简历里出现女子学院、女性社团经历的，评分普遍被压低。项目最终被整体废弃。机器没有性别观念，它只是忠实地复制了历史数据里的不平衡。

KC: 算法公平 :: 算法公平不是要求对所有人输出相同结果，而是要求不同群体不被系统性歧视——衡量它要看分组表现，而不是只看平均分。:: 生活里的例子 :: 整体准确率 95% 的识别系统，可能对某个群体只有 80%，平均分把问题悄悄藏了起来。
FIG: 两张成绩单对比：左边「全体平均 95 分」一片绿色；右边按三个群体拆开的分项柱状图，其中一根柱子明显矮一截标红；下方标注「只看总分 vs 分组体检」 :: 检验公平的钥匙是分组统计：总分离谱漂亮时，更要看看每一组各自多少分
P: 这个案例教给我们两件事。第一，偏见不一定来自恶意，更多时候来自数据的惯性：过去谁被录用得多，模型就学成喜欢谁。第二，发现偏心靠的不是良心发现，而是制度化的检查——把测试人群分组，分别统计通过率、错误率，让差距无处藏身。
P: 换个场景再看偏见如何伤人。语音助手听不懂方言使用者的认真表达，拍照软件曾把亚裔面孔误标成闭眼，某些内容审核系统对特定语言的处理明显更粗糙。这些案例的共同点是：被亏待的群体并没有做错什么，他们只是不在设计者的默认想象里。
P: 公平还有更微妙的一面：同一套数字，可以有几种互相冲突的公平定义。「每人答同样的题」是一种平等，「给起点低的人适当加权」是另一种，两者在数学上常常不可兼得。所以设计者必须先回答价值问题：这个场景里，我们要的是哪种公平？这是技术无法替人做的决定。
CALL: 想一想 :: 学校分配竞赛名额：「完全按分数取前二十名」和「每班至少一个名额」，分别保护了哪种公平？牺牲了哪种？你倾向哪种，为什么？

S: 谁来当公平的守门员
P: 既然模型自己不会喊冤，守门就得靠流程。负责任团队的标准做法包括三道工序。开工前审查数据来源：样本覆盖了哪些人群、缺了谁？开发中做偏见测试：用专门构造的对照样例试探模型是否区别对待。上线后持续监测：真实世界在变，昨天合格的系统今天可能走歪。
P: 第三方审计也在兴起，就像财务报表要请会计师事务所核查一样，重要算法开始接受外部机构的独立检验。有些地区已经立法要求高风险系统（招聘、信贷、司法辅助）必须提交合规证明。监督成本不低，但和系统性歧视的社会代价相比，这笔钱花得值。
P: 作为普通用户也有参与方式：遇到明显离谱的结果（比如照片审核误判、语音助手听不懂你的话），可以通过反馈渠道投诉。每一次投诉都是一次免费的偏见测试数据。集体的较真，会倒逼产品改进——公平从来不是施舍来的，是被要求出来的。
KC: 分组检验法 :: 检验算法公平的标准动作是把测试人群按群体拆开，分别统计通过率与错误率，让被平均数掩盖的差距现出原形。:: 试一试 :: 全班平均视力 5.0 不代表每组都达标——分小组统计才知道谁需要帮助。
CALL: 动手演练 :: 设计一份「AI 班干部评选系统"的公平检查清单：列出至少四条检查项，覆盖数据、分组表现、申诉渠道三个方面。

S: 小结与预告
P: 回顾本章：偏心可以来自无恶意的数据惯性，招聘翻车案是最生动的教材；检验公平靠分组统计而非平均分；公平的定义本身存在取舍，需要人来做价值决断；守门要靠审查、测试、监测与外部审计的全流程。
P: 就算天平调平了，还有一个更深的不安：模型凭什么给出这个结论？如果连工程师都说不清判断理由，被影响的人该向谁追问？下一章进入黑箱内部。
