T: 看不见的神经：城市里的传感器

P: 除了固定设备，还有一些移动的感知节点容易被忽视：公交车本身就是移动传感器，记录沿途的路况和乘客量；环卫车加装了摄像头可以巡查道路破损；甚至共享单车的 GPS 轨迹也能反映哪些街道更适合骑行。城市里的每一辆移动车辆都可能是一个行走的观测站。

S: 城市寻宝第一站：十字路口
P: 如果把智慧城市比作一个巨人，传感器网络就是它遍布全身的神经系统。第一站我们来到最熟悉的十字路口：路口四个方向埋着地磁线圈，车辆碾过会引起磁场变化，系统由此统计车流量；杆件上的摄像头识别车流排队长度；有些城市还装有噪声监测和气象探头。一个不起眼的路口，竟藏着五六种感知设备。

P: 第二站：公交与地铁。刷卡机的每一次嘀声都是一条出行数据——匿名汇总后就能画出全市的客流热力图：哪条线最挤、哪个时段需要加开班次，一目了然。第三站：公园与街道。空气质量微站每小时报出 PM2.5 数值；智能垃圾桶内的满溢传感器提醒清运车「我饱了」；井盖下的水位传感器在暴雨天预警内涝风险。
CALL: 动手实践 :: 在上学路上做一次「传感器侦察」，记录你发现的所有可疑设备（不用碰），猜猜它们各自在感知什么。

P: 传感器也有「体检」：运维人员定期校准读数、清洁探头、更换电池。一台失准的传感器比没有更糟——错误数据会带偏整个决策。所以成熟的城市系统都配有数据质量监控，自动标记异常读数。
P: 数据安全也是传输环节的重要课题：市民的出行数据如果被不当使用，可能暴露个人行踪规律。因此成熟的城市系统都会对原始数据脱敏处理——只保留统计所需的群体特征，抹去能定位到个人的标识。技术与规则的配合才能让数据的利用不越界。

S: 数据从街头到云端
P: 传感器收集的数据去哪了？它们的旅程分三跳。第一跳：通过 4G/5G 或物联网专用网络传到汇聚点；第二跳：数据平台清洗整理——去掉明显错误的读数、统一格式；第三跳：存入数据库供分析调用。整个过程全自动、秒级完成，这正是千万个传感器能协同工作的原因。
P: 有个细节体现工程智慧：不是所有数据都需要实时上传。垃圾桶满了才发一次通知，比每隔一分钟汇报一次「还没满」省电得多。工程师会按需设计上报频率——变化慢的少报，变化快的多报。好系统的聪明之处在于知道什么值得说。
CALL: 想一想 :: 为什么空气质量数据要每小时更新，而红绿灯配时数据需要每几秒更新？从「决策需要的速度」角度思考两种数据的差异。

P: 城市传感器的数量还在快速增长：据行业报告，全球物联网连接设备已超过百亿台，其中相当比例部署在智慧城市场景中。你所在城市的传感器数量可能比公交站还多——只是它们太安静了，安静到你从未把它们当作一座城市的组成部分来看待。

S: 小结与预告
P: 回顾本章：城市的路口、公交、公园藏着五花八门的传感器；数据经传输、清洗后进入平台供分析；上报频率按决策需求精心设计。城市的神经末梢已经摸清，接下来看大脑如何用这些数据做决策——就从每天陪你等红灯的那盏信号灯说起。
