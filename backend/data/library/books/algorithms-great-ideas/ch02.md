T: 永远走最近的门：Dijkstra 最短路径

S: 导航软件的心脏
P: 你在地图上输入目的地，一秒钟后路线出现，还贴心标着预计时间。这一秒里，导航软件在一张包含亿万条道路的图上算出了从你到终点的最短路径。支撑它的经典算法是 Dijkstra 算法（读作狄克斯特拉），诞生于 1956 年，至今仍是导航系统的核心引擎之一。
P: 先把问题翻译成图的语言：路口是节点，道路是边，通过时间或距离是边的权重——求最短路就是求两节点间权重总和最小的路径。注意权重可以自定义：通勤高峰时把「时间」设为权重，货车司机把「费用」设为权重，同一个算法服务完全不同的目标——这个 1956 年诞生的算法就叫 Dijkstra。|mark:Dijkstra

KC: Dijkstra 算法 :: Dijkstra 从起点出发，每轮确认一个当前距离最近且未确定的节点，并用它更新邻居的距离，逐步向外扩张直至覆盖全图；要求所有边权重非负。:: 生活里的例子 :: 洋葱剥一层看一层：永远先处理离中心最近的那一圈，由内向外推进。
P: 算法的策略是一条铁律加一个循环。铁律：已确认最短路的节点绝不反悔（贪心）。流程：起点距离记零、其余记无穷大；每轮从未确定的节点里挑距离最小者，宣布「到它的最短路确定了」；然后检查它的每个邻居——如果经它中转更近，就更新邻居的距离和来路。重复直到终点被确认，再沿着来路回溯就是完整路线。

P: 用伪代码整理成四步骨架：「起点的距离设为零，其余全部设为无穷大；当还有未确定的节点时——挑出其中距离最小的那个节点并确认它，再对它的每个邻居检查：若经过它中转更近，就更新邻居的距离与来路」。四行之外全是细节工程：真实系统用优先队列让「挑最小」一步到位——但思想骨架六十多年没变过。

CALL: 动手推演 :: 在纸上画五个节点六条边的加权图，手动执行两轮 Dijkstra：每轮写出选中的节点与被更新的距离。检查你是否理解了「贪心扩张」。

S: 边界条件：什么时候不能用
P: Dijkstra 有个前提：所有边的权重必须非负。原因藏在贪心逻辑里——「确认的节点不再反悔」依赖一个事实：绕道不可能更近。一旦出现负权重（比如某些路段倒贴钱），先走远路反而省的悖论就会出现，贪心策略彻底失效。这类问题要换 Bellman-Ford 等专门算法处理。知道工具的适用边界，比记住工具本身更重要。
P: 它还有一个著名的兄弟问题值得分辨：旅行商问题问的是「遍历所有城市一次再回来的最短路线」，看起来相似，难度却是天壤之别——前者多项式时间内轻松求解，后者属于最难的计算类别，城市一多只能靠近似。分清「最短路」和「遍历路」，是算法面试里的经典陷阱题。
P: 现实应用远不止导航。网络数据包的路由选择、电路布线、游戏里怪物的寻路（配合网格化地图），甚至语言编辑器计算单词的最小编辑距离，都是同一思想的变形。学会一个核心算法，等于点亮一片应用大陆。
KC: 松弛操作 :: 每确认一个节点就检查「经它中转是否让邻居更近」，若更近则更新邻居的距离与来路，这个动作叫松弛，是 Dijkstra 的核心引擎。:: 试一试 :: 用「经中转更便宜」检查一次换乘方案。
CALL: 动手实践 :: 给你的校园画一张简化地图：教学楼为节点、步行时间为权重，用 Dijkstra 手动算出食堂到图书馆的最快路线，再实地掐表验证误差。

S: 小结与预告
P: 回顾本章：Dijkstra 用「每次确认最近未定点并向外松弛」的贪心扩张求单源最短路；要求权重非负；伪代码四行、工程细节丰富；它与旅行商问题形似而难度天壤。
