T: 小项目：班级图书角管理表

S: 先当设计师再动手
P: 毕业项目开工。任务：为班级图书角搭一套借阅管理表，要求能记录每笔借还、自动统计每人借阅量和每种书的库存、随时生成排行榜和占比图。先别急着开软件——好项目从设计开始。拿张草稿纸回答三个问题：谁会用这张表？他们需要看什么？数据怎么进来？|mark:设计
P: 设计答案示例：使用者是图书管理员同学和班主任；管理员要看「今天该催谁还书」，老师要看「本月阅读趋势」；数据由管理员每次借还时手工登记一行。由此推出表格结构：一张流水表记录每笔借还（日期、书名、借阅人、状态），几张统计区用公式自动汇总——原始数据只录一遍，其余全自动。
FIG: 一张架构草图：左侧「借阅流水表」四列图标，箭头分三路通向右侧三块面板——「人均借阅统计」「书籍库存余量」「月度趋势图」，每块面板旁标注所用技能（COUNT/公式/图表） :: 一次录入，多处自动汇总：好系统的标志是重复劳动归零

S: 分步搭建
KC: 条件计数 :: COUNTIF 函数按指定条件统计数量：数一数整列数据里某个名字总共出现了几次，短短一行公式就完成人工清点半天的活儿。一行成人工半天的工作。:: 试一试 :: 统计值日表中每位同学本周的上岗次数。
P: 第一步建流水表：A 到 E 列分别是日期、书名、借阅人、类别、状态（在借或已还）。填入十来条真实感十足的模拟记录备用。第二步做个人统计区：一列不重复的姓名（手动列出即可），旁边用 COUNTIF 类的条件计数函数统计每人借阅次数——语法如「=COUNTIF(C:C, "小明")」，意思是数一数 C 列里有多少个小明。
P: 第三步做库存区：每种书的「在库数量」等于总册数减去状态为「在借」的该书数量。第四步插入两张图：人均借阅柱状图与书籍类别饼图，标题写成结论式。第五步设置筛选：给流水表打开筛选开关，管理员想催书时筛一下状态列即可。
CALL: 动手挑战 :: 给系统加一个「超期提醒」辅助列：登记日期超过十四天且状态仍为「在借」的行自动显示「催」字。提示：可以用 IF 函数比较日期。

S: 上线与迭代
KC: 迭代日志 :: 上线只是开始：把每次使用中发现的问题与对应修改记成日志，工具才能随真实需求持续生长而不是逐渐荒废。:: 试一试 :: 为自己的管理表开一篇使用记录，每次改动记一行。
P: 系统上线后的一周才是真正的考验。你会遇到真实世界的麻烦：有同学名字写了同音字导致统计分裂；有人借走的书没登记；两个管理员同时改表互相覆盖。每个问题都是迭代的机会——名字统一用学号代替？加一条「借书必登记」的班规？把文件放到共享位置并约定编辑时段？
P: 项目完成后别忘了做一次备份：把文件另存一份带日期的副本，或者存到云端网盘。辛苦搭好的系统一旦因为电脑故障丢失，重建要花整整两节课的时间。数字时代的基本素养之一，就是重要成果永远至少存在两个地方。
P: 记录下你做的每一次修改和它解决的问题，这份迭代日志是项目最珍贵的部分。工具的价值不在一次搭得多漂亮，而在能不能随着使用者的真实需求持续生长。软件如此，人生中你将经手的大多数事情都如此。
P: 全书回顾：第一章的门牌思维让数据有了秩序；第二章的公式让计算自动化；第三章的排序筛选把检索压缩到秒级；第四章的图表让结论可视化；第五章把它们拧成一件持续服务集体的作品。表格里的数学脑，本质是一种「让结构替人干活」的智慧。
P: 这套智慧可以迁移到任何地方：家庭开支表、运动训练记录、社团活动台账……下次遇到「反复手工整理某件事」的场景，试着问一句——它能变成一张会自己算的表吗？
