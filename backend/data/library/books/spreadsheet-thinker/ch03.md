T: 排序与筛选：快速找到答案

S: 排序：一秒钟的重新列队
P: 面对五十行借书记录，想找「借书最多的人」，肉眼扫描要几分钟，还容易看漏。排序功能一键解决：选中数据区域，点「数据」菜单里的排序，选择按借阅数量降序——最多的人瞬间跳到第一行。降序从大到小，升序从小到大，数字、日期、拼音都能排。|mark:排序
@kp=sort-filter
KC: 排序与筛选 :: 排序按某列的大小或字母顺序重排所有行；筛选只显示满足条件的行、暂时隐藏其余。两者都改变你看到的视图而不删数据。:: 生活里的例子 :: 操场集合按身高排队是排序；老师说「戴眼镜的出列」是筛选。
KC: 筛选漏斗 :: 多列筛选条件会自动叠加生效，候选范围层层收窄如同漏斗，帮助精准锁定目标行；一旦取消筛选，被隐藏的行的行全部回来。:: 试一试 :: 先筛出某个小组，再筛出其中借书超过八本的人。
P: 排序前还有个保命习惯值得培养：给数据区加一行序号列，从 1 编到最后一行。万一排序结果看起来不对劲，按序号列升序排回去就能一键还原原始顺序。这相当于给数据留了一条回家的路，操作再激进也不怕迷路。
P: 排序有一个必须警惕的细节：整行要一起动。如果只选了一列去排序，表格可能弹出提醒——因为姓名和分数是绑在一起的，分数排了队而名字原地不动，数据立刻张冠李戴。正确做法是让光标待在数据区里任一格再点排序，软件会自动把整个连续区域视为一体重排。

P: 多条件排序也特别值得一学：先按小组升序排列，同一个小组内部再按借阅数量从高到低降序排列，仅仅一次点击就能实现「组内排名」这种班级管理中最常见的实际需求。
P: 多条件排序也值得一学：先按班级升序，同班里再按借阅量降序。在排序对话框里添加第二个关键字即可。这种「组内排名」的需求在成绩单、比赛计分里随处可见，学会它，班主任的很多手工活都能交给你了。
CALL: 动手实践 :: 给你的借阅表做一次双关键字排序：先按负责小组分组，再按每人借书量从高到低排，观察表格结构发生了什么变化。

S: 筛选：只看我关心的
P: 排序解决「谁最多」，筛选解决「哪些是」。点击数据区任一格，打开「数据」菜单里的筛选，每个表头会出现小三角。点开「负责区域」的下拉框，只勾选「黑板」——全表瞬间只剩擦黑板的记录，其他行悄悄隐藏（注意是隐藏，不是删除，取消筛选全部回来）。
P: 筛选的强大在于条件组合。数字列可以筛「大于 5」的记录；文本列可以勾选多个值；多列同时筛选时条件自动叠加——先筛出「三组」，再筛「借书超过 10 本」，两步就锁定了既在三组又高产的同学。层层收窄，像漏斗一样精准。
P: 筛选还有一个隐藏福利：筛选后的统计只针对可见行。先筛出三组的记录再看合计数，得到的就是三组自己的总量。排序管秩序、筛选管视野、统计管结论，三者是天然无缝的铁三角。
P: 把两个高手配合使用更是威力翻倍：先筛选出本月的记录，再对结果按金额排序——月度消费冠军立刻现形。排序管秩序，筛选管视野，一个重排队列，一个收窄范围，几乎所有「帮我找」类问题都是这两招的组合拳。
P: 动手完成一组检索挑战：在你的图书角表中找出借书最少的一位同学；找出所有上周五登记的记录；找出三组中借书超过八本的同学名单。每题限时三十秒，体会一下工具带来的速度感。
CALL: 想一想 :: 为什么说「筛选只是藏起来而不是删掉」这一点很重要？想象一次误操作筛选后直接保存发给老师的场景。

S: 小结与预告
P: 回顾本章：排序一键重排队列，务必整行联动；多关键字实现组内排名；筛选按条件隐藏无关行，多列叠加形成漏斗；两者组合是检索类问题的万能钥匙。
P: 数据已经会算、会找了，但汇报时贴一堆数字仍然不够直观。下一章请出表格软件的颜值担当：图表，让数据自己开口说话——图表是数据汇报的颜值担当，也是结论的放大镜。。
