KC: 图形化运动控制 :: 图形化编程用拖拽积木设定左右马达的速度与持续时间，组合出前进、后退、转向、停止等动作序列。:: 生活里的例子 :: 像给两位短跑运动员分别下口令：左边跑八成速度三秒，右边全速三秒——结果就是向左画弧。
KC: 直线校准 :: 两只马达出厂存在个体差异，名义同速实际不同速；逐次微调一侧的速度补偿值直到直线笔直，并把数值登记存档。:: 试一试 :: 以加减五为步长寻找最直的速度组合。
P: 打开套件配套的编程软件（多数套件用拖拽积木的方式，原理与 Scratch 相通），找到运动类积木：「设置左马达速度」「设置右马达速度」「等待几秒」「停止全部」。拼出你人生第一段机器人程序：左右马达都设 60，等 2 秒，全部停止。下载到主控，按下运行——小车动了！
P: 立刻做个小实验理解差速转向。程序一：两轮同速 60 跑 2 秒——直线。程序二：左轮 40 右轮 80 跑 2 秒——向左画弧。程序三：左轮负 60 右轮 60——原地左转一圈。三个实验做完，「速度差即转向」从知识变成了手感。
FIG: 三条轨迹示意：第一条两条平行直线标「同速直行」；第二条向左弯的弧线标注「左慢右快」；第三条一个原地圆圈标注「左右反转」；每条轨迹旁配对应的积木参数小图 :: 左右轮的速度差就是方向盘：差多少、转多急，全由数字说了算
P: 有个数值细节要留意：很多套件的速度范围是负百到正百，零代表停止。想让小车又快又稳，别直接拉满一百——满速时惯性巨大，刹车距离惊人。实战里六七十的巡航速度配合提前减速，往往比全程狂奔更快完成赛道。
CALL: 动手实验 :: 编一段「走正方形」程序：直行一秒、右转零点五秒，循环四次。跑完后测量：它画出的是标准正方形吗？偏差出现在哪一步？

S: 校准：让数字对上现实
P: 你大概率会发现：同样的速度值，小车不走直线。原因很物理——两只马达出厂就有个体差异，加上地面摩擦不均，名义上的「同速」实际不同速。解决办法叫校准：微调某一侧的速度补偿值，反复试到直线笔直为止。把最终补偿值记在标签上贴到底盘，这是每台车的专属档案。
CALL: 动手校准 :: 给你的车做一次直线校准：记录初始偏转方向，按每次加减五的步长调整一侧速度，找到最直的组合并登记成档。
P: 编程软件里还有一个新手必知的按钮：下载与运行的区分。下载是把程序从电脑传进主控板存起来；运行是让主控板执行已存的程序。改完代码忘记重新下载，跑的还是旧版本——这是初学者排行榜第一名的经典乌龙，几乎人人都中过招。
P: 校准的价值远不止跑直线——它教会你一个硬件项目的核心观念：代码里的数字只是意图，现实永远需要校对。程序写六十不代表轮子真转百分之六十的力量，中间隔着电池电量、地面材质、马达脾气。承认并拥抱这些不确定性，是动手学科与纯软件最大的不同。
P: 回顾本章：接线要对接口编号；四块积木就能驱动小车；速度差即转向；满速未必最快；校准让数字对上现实。你的车已经会跑了，但它还是个瞎子——全靠预设时间瞎走。下一章给它装上眼睛。
