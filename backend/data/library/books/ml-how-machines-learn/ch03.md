T: 蒙眼下山：梯度下降

S: 一场暴风雪中的任务
P: 想象你被空投到一片山区，任务是抵达山谷最低点。糟糕的是浓雾弥漫、能见度为零，你蒙着眼，看不见地形全貌——这几乎就是模型面对损失函数的处境：百万个参数构成起伏的地形，海拔是损失值，而它只能局部感知脚下的坡度。
@kp=gradient-descent
KC: 梯度下降 :: 梯度下降每一步都用脚感探测当前位置最陡的下坡方向，朝那个方向迈出一小步，重复千万次直至走到谷底附近。:: 生活里的例子 :: 闭眼在碗里滚动的玻璃珠：永远沿碗壁最陡处下滑，最终停在碗底的低点。
FIG: 一条起伏的山脊线，山上站着一个小人；小人脚下画着两个箭头——实线长箭头标「最陡下坡方向」，虚线短箭头标「本步位移」；山丘顶端另有一个小人标注「随机起点」 :: 每一步只依赖脚下的局部信息：方向取最陡下坡，长度由步幅决定
P: 方向问题就此解决：不需要看见全山，只需要知道脚下往哪边更低——数学工具「梯度」给出的正是最陡的上坡方向，反着走就是最快的下坡路。这个设计的精妙在于把一个全球性难题（找全山最低点）拆解成无数次局部判断（这一步往哪走），每次只需极少的计算。
P: 步长则是艺术活，机器学习里叫学习率。步子太小，一亿步还没走出多远，训练慢得令人发指；步子太大，一步跨过谷底落到对面山坡，来回震荡甚至越荡越高直接发散。工程师调参时反复试的往往就是这个数字——太大看曲线爆炸，太小看进度龟速。
CALL: 想一想 :: 下山途中可能遇到小水洼（比周围都低的坑）。站在洼地里四周全是上坡，蒙眼的人如何知道自己还没到真正的山谷？这对应模型训练里的什么现象？
P: 把类比翻译回伪代码，训练循环的第三行就落地了：「重复直到损失不再明显下降——对每个样本做预测，算出损失；计算损失对参数的梯度，也就是最陡上坡方向；然后更新参数，新参数等于旧参数减去学习率乘以梯度」。

P: 注意减号：梯度指向上坡，我们要下坡所以取负。现代深度学习的训练动辄数百万次迭代、参数以十亿计，但骨架始终是这几行。工程上的种种花活——动量、自适应步长、批量采样——都是在给这套朴素框架打补丁提速。
P: 还有一处值得点破：梯度下降找到的是「某个低谷」而不是「唯一最低谷」。起点不同、步长不同，终点可能不同。听起来是缺陷，实践中却常因祸得福——深谷未必是好谷，模型世界里的最优解哲学远比考试题宽容。
KC: 学习率 :: 学习率是梯度下降每一步的步长：太小训练进展缓慢，太大则在谷底两侧来回震荡甚至发散，是需要反复调试的关键参数。:: 试一试 :: 蒙眼走一段已知下坡路，分别用半步和两大步体会两种失败模式。
CALL: 动手模拟 :: 在纸上画一条波浪曲线当作山地，让同学闭眼用笔尖从随机点出发：每步先用手感受两侧哪边纸面「更低」（你口头报出高度），走二十步记录轨迹。

S: 小结与预告
P: 回顾本章：梯度下降把全球寻优拆成局部导航——方向取最陡下坡，幅度交给学习率；学习率过大震荡发散、过小进展缓慢；训练骨架三行伪代码千年不变；找到的多是「某个」低谷而非理论最低点。
P: 现在我们的模型会学习了，但它学得一定好吗？有一种失败模式格外狡猾：训练成绩近乎满分，实战却一塌糊涂——模型没有学会规律，而是背下了答案。下一章解剖机器学习最著名的病症。
