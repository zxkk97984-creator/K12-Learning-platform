T: 诚实的考试：训练集与测试集

S: 一个自欺欺人的实验
P: 先看一个错误示范。某同学训练了一个「预测期末成绩」的模型，然后拿同一批数据评估，宣布准确率百分之百。问题在哪？模型可能只是背下了这批答案——用练习册当考卷，满分毫无意义。评估的铁律由此而来：考核数据必须是模型从没见过、参与过学习的。|mark:评估
@kp=train-test-split
KC: 训练集与测试集 :: 把数据随机分成两部分：训练集供模型学习，测试集在训练完全结束后才用于打分。只有测试成绩才代表真实水平。:: 生活里的例子 :: 高考题绝不会出现在你刷过的任何一本教辅里——隔离才能测出真功夫。
FIG: 一摞数据卡片被随机分成两堆：大堆（约八成）标着「训练集·教材」进入学习区；小堆（约两成）装进信封封口标「测试集·密封考卷」，直到最后一步才拆封 :: 划分的全部意义在于那道「封存」手续：考卷在放榜前绝不能被偷看
P: 常见的划分比例是八二或七三，前提是随机打散——如果恰好把最难的样本都划进测试集，成绩会低估；把时间上更晚的数据混入训练，则可能高估（模型提前「看到未来」）。严谨的实践还会按类别分层抽样，保证两边的人群构成比例一致。
CALL: 想一想 :: 医疗诊断模型的测试集中若混入了同一位患者的多次检查记录，会高估还是低估性能？提示：模型可能认出的是「这个病人」而不是「这个病」。

S: 数据泄露：看不见的作弊
P: 隔离原则最大的敌人叫数据泄露——测试信息以隐蔽渠道渗入训练过程。典型场景包括：在划分之前就做了「用全体数据的平均值填空缺」这类预处理；特征里混进了答案的影子，比如预测「是否违约」时留着一列「逾期后的处理结果」。泄露不报错、不警告，只悄悄送给你一份虚假的高分。
P: 防泄露的核心纪律是流程顺序：先切分，再做一切。所有统计量、标准化参数、特征筛选只在训练集上计算，然后把同样的规则套用到测试集上。更进一步的做法是交叉验证：把数据轮流切成几份，每份各当一次考卷，取平均成绩——单次划分的运气成分就被抹平了。
P: 还有一层容易被忽视的时间纪律。预测股价、天气这类带时间顺序的任务，必须按时间先后切分：用过去预测未来。若让模型「提前见到」下个月的数据再回头预测本月，成绩会漂亮得可疑——这不是本事，是穿越。凡是数据自带时间轴的场景，随机划分都要慎用。
P: 诚实评估的最后一块拼图是基线对照。上线一个复杂模型前，先跑一个笨办法当参照：比如「永远猜多数类」或简单规则。新模型若只比笨基线好一点点，它的复杂度就不值当。基线像一把标尺，专门治「为炫技而建模」的行业通病。
P: 到这里，监督学习的完整生命周期已经闭环：定义损失、梯度下降调参、管理过拟合、诚实评估。四块零件严丝合缝地咬合在一起——你已经掌握了这门手艺的主干骨架。
KC: 数据泄露 :: 数据泄露指测试集的信息经隐蔽渠道混入了训练过程，如划分前就做了全局统计或特征里藏着答案的影子，会送出虚假的高分。:: 试一试 · 检查一段分析代码：所有统计量是否只在训练集上计算？
CALL: 动手审计 :: 某同学声称他的模型准确率 99%，但你能提问三次来查证。你会问哪三个问题？参考方向：数据怎么切的、有没有泄露风险、和什么基线比。
