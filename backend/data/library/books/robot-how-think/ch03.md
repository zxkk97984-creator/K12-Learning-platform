T: 大脑如何决定：规则与状态

S: 最简单的脑子：如果就
P: 机器人大脑里最初级的思考方式，你其实早就见过——编程课上的条件判断。翻译成机器人语言就是：「如果前方距离小于二十厘米，就右转；否则直行。」把几条这样的规则叠在一起，一台会绕障碍的小车就诞生了。规则写得好不好，直接决定机器人是机灵还是莽撞。|mark:条件判断
P: 规则式决策有个天然优点：好解释。机器人为什么撞了墙？翻出程序一看，原来漏写了「玻璃门」这条情况。它不像人找借口，错在哪条规则清清楚楚。调试机器人因此变成一件很有侦探乐趣的事：观察怪异行为，倒推哪条规则出了问题。
P: 但纯规则堆多了会打架。「有障碍就右转」和「靠右循线行驶」同时触发时，机器人该听谁的？它在墙边循线时恰好遇到障碍，可能陷入原地打转的死循环。规则数量一多，互相冲突的概率暴涨，工程师管这叫规则爆炸。出路不是加更多规则，而是换一种组织思路。
CALL: 想一想 :: 一台既要在走廊居中行驶、又要避开突然出现的同学的机器人，两条规则会在什么场景下打架？试着描述那个尴尬瞬间。

S: 聪明的组织术：状态切换
@kp=robot-state
KC: 状态与状态切换 :: 状态指机器人当前所处的行为模式，如巡逻、避障、返回充电。每个状态内部只运行自己的规则，满足特定条件就切换到另一个状态。:: 生活里的例子 :: 手机有静音、震动、响铃三种模式，闹钟响了怎么提醒取决于当前模式——这就是状态思想。
FIG: 状态图：三个圆圈分别标着「巡逻」「避障」「返回」，圆圈之间画着带条件的箭头：「发现障碍」从巡逻指向避障，「障碍消失」指回巡逻，「电量低于两成」从任意状态指向返回 :: 把复杂行为拆成几个状态，每个状态专心做一件事，切换条件就是状态之间的桥
P: 状态思想的妙处在于分而治之。巡逻状态下只操心沿中线走；一旦超声波报告近距离障碍，立刻切进避障状态，此时循线规则暂时让位；障碍解除再切回巡逻。任何时刻只有一套规则在主导，打架问题迎刃而解。家里的扫地机、商场的送餐车，骨子里都是这套架构。
P: 设计状态机有个实用口诀：先列状态，再画箭头。拿便签纸把所有行为模式各写一张，问自己两个问题——什么情况下进入这个状态？在这个状态里等到什么信号才离开？两张清单写完，箭头自然浮现。箭头没覆盖到的死角，就是未来卡死的隐患。
P: 更高级的机器人还会给状态装「记忆」。比如搬运机器人记住「目标货架在三号位」，途中被人群挡路绕了两圈，仍能继续朝三号位前进。记忆让状态从「条件反射」升级为「带着目标的行动」，这也是下一章反馈机制的入口。
KC: 状态机口诀 :: 设计状态机先列状态、再画箭头：每个状态写下进入条件和退出条件，箭头没覆盖到的死角就是未来卡死的隐患。:: 试一试 :: 用三张便签纸给电风扇画出「关闭、摇头、定向」三个状态之间的切换箭头。
CALL: 动手设计 :: 给一台教室值日机器人设计三个状态（擦黑板、摆桌椅、回充电桩），写出每个状态的进入条件和退出条件，注意别留死角。

S: 小结与预告
P: 回顾本章：如果…就…的规则简单透明但容易打架；状态切换把复杂行为分成互不干扰的模式，是机器人程序的主流骨架；先列状态再画箭头，设计就不会漏。大脑的思考方式清楚了，还差最后一环——决定如何变成动作。
P: 「右转」两个字怎么变成轮子的转动？转多少度才算右转？转过头了又该怎么办？从决定到动作之间还有最后一公里要走。下一章我们走进执行器与反馈的世界，看看指令如何落地，误差如何在半路上被悄悄消化掉。
