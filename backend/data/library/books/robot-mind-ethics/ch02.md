S: 从课堂走进代码
P: 经典电车难题：失控的电车将撞死五人，你可以扳动道岔让它转向、只压死一人——扳吗？半个多世纪里它只是哲学课的思想实验。自动驾驶的出现改变了这一切：避险算法必须在碰撞不可避免时做出真实的选择，而且要提前写成代码。哲学假设变成了工程必答题。|mark:电车难题

KC: 电车难题 :: 电车难题揭示道德判断的冲突结构：结果主义看救人数目，义务论看是否主动伤害他人；两者常给出相反答案。:: 生活里的例子 :: 转向会撞上护栏里的修路工人，直行则可能撞上违规横穿的行人——系统必须预先决定优先级。

S: 全球两百多万人的答案
P: 麻省理工学院的「道德机器」在线实验收集了二百三十三 个国家和地区、数千万人次的抉择数据。结果呈现出有趣的共识与文化差异：全球普遍倾向保护人类而非动物、保护年轻人而非老人、保护更多人而非少数人。但分歧同样鲜明：对「是否应优先保护遵守规则者」，不同文化圈的态度差异巨大。
P: 这些数据的价值不在给出标准答案，而在揭示一件事：不存在全人类一致的道德排序。任何写进代码的取舍都只是某种局部共识。这直接引出工程与政策的分工建议——技术层面尽量避开伤害（更好的感知、更早的刹车），价值层面的排序交给公开的社会讨论与立法程序，而不是工程师在深夜独自拍板。

S: 超越难题的现实智慧
P: 值得庆幸的是，现实中的自动驾驶大部分工作不是解难题，而是避免难题出现：更远的激光雷达探测、更早的风险预判、保守的车速策略。行业里有个说法：最好的避险算法是让电车根本开进不了那个岔路口。把伦理困境压缩到极小概率区间，比在困境中选边更有工程价值。
P: 同时，责任框架必须先于事故存在。等级划分（L0 到 L5）明确了每个自动化级别下谁负责监控、谁负责兜底；运行设计域限定系统只能在哪些条件下自主工作。这些制度设计的共同目的：无论技术多先进，「有人在为安全签字」这件事不能消失。
P: 动手完成一次角色扮演辩论。全班分成三组：车企代表论证「保护乘客是产品责任」；行人团体论证「道路是公共空间」；监管方提出兼顾方案。最后共同起草一份含三条规则的《自动驾驶本地原则》。
KC: 责任先行原则 :: 自动驾驶伦理的制度设计核心：自动化等级明确谁监控谁兜底，运行设计域限定自主范围——无论技术多先进，「有人为安全签字」不能消失。:: 试一试 :: 查一查自动驾驶 L0 到 L5 分级中各级别的责任主体分别是准。
CALL: 动手实践 :: 写下你个人的三条避险优先级并说明理由，然后与家人讨论——你会发现连最亲近的人之间也存在分歧，这正是该问题百年未决的原因。

S: 小结与预告
P: 回顾本章：自动驾驶把电车难题从思想实验变成工程必答题；全球实验显示共识与分歧并存，不存在普世排序；现实智慧在于用技术压缩困境出现的概率，用制度保证责任始终有主。
P: 离开了公路，下一站是更精密也更沉重的场景——手术台。当机械臂握着手术刀，主刀医生的手放在急停按钮上，责任的天平该如何摆放——把分歧写下来，比强行一致更有价值。
