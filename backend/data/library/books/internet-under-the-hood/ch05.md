T: 快与稳的艺术：缓存、CDN 与加密

S: 第一件：把数据搬到离你近的地方
P: 物理距离是网速的硬约束——光在光纤里跑也需时间，跨国往返轻松吃掉上百毫秒。工程师无法缩短地球，但可以把数据搬近：这就是内容分发网络（CDN）的思路。网站把自己的图片、视频、静态页面复制到全球几百个节点机房，用户访问时自动分配到最近的节点取货。
@kp=cache-and-cdn
KC: 缓存与内容分发网络 :: 缓存是把常用数据存在就近处以省去重复获取的通用手段；CDN 把站点内容铺满全球节点，让每个用户都享受「同城速度」。:: 生活里的例子 :: 连锁超市把货铺到你家附近的门店，而不必每买瓶水都跑总厂。
FIG: 一张世界地图示意：中心一颗星标「源站服务器」，四周散布多个小仓库图标标「CDN 节点」，不同城市的用户各自连向最近的节点，连线粗细代表延迟高低 :: 源站只应付节点进货，海量用户的请求被节点就地消化
P: CDN 之上还有一层更贴近你的缓存——浏览器缓存。网页里的 Logo、样式表这些不常变的内容，第一次访问后就被存在本地；下次再访，浏览器直接用存货，请求都不必发出。配合第三章 DNS 的缓存、第四章服务器自己的缓存，一条「缓存金字塔」贯穿全程，每一层都在替上一层挡流量。
CALL: 想一想 :: 网站更新了首页图片，为什么有些老用户看到的还是旧图？从缓存金字塔的角度解释，并想想站长可以用什么办法强制大家看到新版。

S: 第二件：给对话上锁
P: 快解决后是安全。HTTP 对话如同明信片：沿途每个路由器都能读到你发的一切——密码、聊天、验证码一览无余。公共 Wi-Fi 上这尤其危险，同网络的任何人都可以截获明信片。HTTPS 是解药：在 HTTP 外套一层 TLS 加密，明信片变成上了锁的信封。
@kp=https-encryption
KC: HTTPS 加密 :: HTTPS 用非对称加密协商出会话密钥，再用它对通信内容对称加密，同时通过证书体系验证网站身份，防窃听也防冒充。:: 生活里的例子 :: 先当面试暗号交换保险柜密码，之后所有信件都用这个密码上锁——偷看者只能拿到锁着的信。
P: 那把小锁背后是一场精巧的双阶段表演。难点在于双方从未见过面，怎么安全约定共同密钥？答案是先用一对数学上的「公私钥」完成初始交接：公钥人人可得，用它加密的信息只有持私钥的一方解得开。密钥谈妥后改用速度快的对称加密传正文。这套流程叫 TLS 握手，发生在你按下回车后的最初几十毫秒里。
P: 加密之外还有身份问题——你怎么确定对话对面真是那家银行？证书体系登场：网站向权威机构（证书颁发机构）申请一份盖了章的证书，声明「这个域名归我」，浏览器内置了这些机构的根名单，验章通过才显示小锁。小锁因此有两重含义：内容加密，且对方验明正身。
P: CDN 和缓存还悄悄改变着内容的形态。你在不同城市打开同一个视频网站，看到的首页海报可能并不相同——系统按你的位置和网络状况分发最合适的版本。个性化与就近服务叠加，让每个人眼中的互联网都略有不同。下次旅行时对比一下酒店电视里的新闻客户端，你或许能发现这种细微差异。
P: 实用守则随之而来：涉及账号与支付，确认地址栏有小锁且域名拼写正确；遇到「证书无效」的红色警告不要强行继续——那可能意味着有人冒名顶替；公共 Wi-Fi 上优先使用 HTTPS 站点与应用。如今主流网站已全面 HTTPS 化，浏览器也会把纯 HTTP 站点标注为「不安全」。
CALL: 动手观察 :: 分别打开一个 HTTPS 网站和任意 HTTP 网址（注意别输入任何账号信息），对比地址栏的差异；点开小锁查看证书详情，找到颁发机构和有效期。

S: 全书回顾
P: 五章走完一次完整的网络之旅：分组交换制定运输制度，IP 地址提供门牌系统，DNS 完成名字翻译，HTTP 规定对话礼仪，缓存与 CDN 提速、TLS 上锁。这些协议各管一段、层层咬合，共同托起你每一次「秒开」的网页——没有魔法，只有分工。
P: 更重要的收获是一副排障眼镜：网页打不开先想 DNS，页面错乱想想缓存，警告弹窗查查证书。技术细节会过时，但这套「分层定位问题」的方法论会长久有效——它正是互联网本身教给你的思维方式。
