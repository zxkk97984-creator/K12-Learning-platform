S: 那零点几秒里发生了什么
P: 在地址栏敲入网址、按下回车，页面几乎瞬间铺满屏幕。这不到一秒的体验里，藏着一场跨越千里的精密接力：你的请求被翻译、切块、逐站转发，服务器的应答原路杀回，浏览器再把代码拼装成画面。本章先看全景路线图，后续四章逐站细讲。
P: 全景共五站。第一站翻译：把域名变成 IP 地址（第三章）；第二站打包：数据切成一个个小包裹准备上路（第二章）；第三站跋涉：包裹经过一串路由器跨网跨洋；第四站对话：服务器收到请求后按 HTTP 规则应答（第四章）；第五站呈现与提速：浏览器渲染页面，缓存让下次更快（第五章）。|mark:路由器

S: 互联网没有总开关
P: 理解互联网的第一性原理是：它没有中心。没有一个机房存着「所有网站」，也没有一台总机调度全部流量。互联网是数亿台设备通过层层网络互相连接的总和，每个网络只负责自己那一小段——正因如此，某个节点损坏时流量可以绕道，局部故障不会全网瘫痪。
P: 这种设计源自它的出身：互联网的前身是美国的一个研究网络，设计目标之一就是在部分设施受损时依然保持通信。去中心化、分布式、可绕行——这些当年为可靠性发明的原则，如今成了支撑全球数字社会的地基。你每次上网都在参与这场无中心的协作。
P: 协作能运转，靠的是所有参与者共同遵守的语言：协议。协议就是事先约定的通信规则——数据怎么打包、地址长什么样、请求如何措辞、错误如何报告。本章路线图上的每一站，都对应一个或几个著名协议：DNS、IP、TCP、HTTP、TLS。学网络，很大程度上就是学这些协议的分工。

KC: 分组交换 :: 分组交换把要发送的数据切成许多带地址信息的小包分别传输，各包独立选路、到达后按序重组，线路由所有用户共享复用。:: 生活里的例子 :: 一本大书拆成几百页分批邮寄，每页信封都写收件人，对方按页码重新装订。
P: 用快递打比方能让全景图更好记：域名解析是查收货地址，打包切块是装车，路由器是各城中转场，服务器对话是签收取件，缓存则是把常用货物提前铺到小区便利店。五个环节对应五种角色，任何一环掉链子都有典型症状。
P: 最后澄清一个常见误解：「网上」不是一个虚拟空间，而是无数实体设备的物理连接——光缆铺在海底，服务器立在建筑里，Wi-Fi 走的是无线电波。所谓云端的轻巧，全靠地面上重工业级的设备在扛。理解了这一点，「互联网是怎么工作的」就变成了可以实地考察的问题。
KC: 协议 :: 协议是通信双方事先约定的规则：数据怎么打包、地址怎么写、请求如何措辞、出错如何报告，所有设备照章办事才能互相听懂。:: 试一试 :: 和同学玩「只许传纸条」游戏，先约定纸条的折法和书写顺序——那就是你们的协议。
CALL: 动手观察 :: 在电脑上运行 ping 命令加任意网站域名（如 ping www.example.com），观察返回的时间数值——那就是一次迷你往返旅行的耗时。

S: 小结与预告
P: 回顾本章：一次网页访问是五站接力的旅程；互联网没有中心，靠协议维持亿万设备的协作；分组交换是它的运输制度。地图已经展开，接下来我们把每一站放大细看——先从运输制度本身开始。
