T: 域名翻译官：DNS 是怎么工作的

S: 没有它，互联网没法用
P: 你能记住几个好友的 IP 地址？一个都记不住。人类擅长记名字，机器认的是数字，DNS 就是站在中间的翻译官：你输入域名，它查出对应的 IP 地址。这个动作叫域名解析，每次上网的第一步都是它——没有 DNS，互联网对普通人等于关机。|mark:DNS
@kp=dns-resolution
KC: 域名解析 :: 域名解析是把域名翻译成 IP 地址的过程，由分层分布式的 DNS 系统完成，结果会被缓存以加速后续访问。:: 生活里的例子 :: 114 查号台：你说公司名，它给你电话号码——号码可能变，但查号台永远知道最新的。
FIG: 一张三层倒立树图：顶端「根服务器」向下分出「.com 顶级域服务器」，再向下分出「example.com 的权威服务器」；左侧一个小人拿着「www.example.com=?」的问询条沿树下行，旁边标注「每层只回答下一站该问谁」 :: 分层问路的智慧：没有任何一台服务器需要记住全世界的答案
P: 完整解析是一场接力问询。你的设备先问最近的递归解析器（通常是宽带运营商提供的）；它若没存答案，就代表你去问根服务器，根说「去问 .com 那一层」；.com 层说「这家域名的档案在某某权威服务器」；权威服务器最终交出 IP。四问四答，通常几十毫秒内完成。
P: 让这套系统扛住全球流量的秘密是缓存。递归解析器会把查到的答案存起来并附一个保质期（TTL），保质期内同样的问询直接秒答，不必再跑全流程；你的电脑和浏览器也各有一份小缓存。全球每天数万亿次解析，绝大多数都被缓存消化在半路。
CALL: 想一想 :: 一个网站刚换了新服务器（IP 变了），为什么有些用户还能访问旧地址长达几小时？用 TTL 的概念解释这种「新旧并存」的过渡期。

S: 当电话簿出问题时
P: DNS 太重要，也因此成为攻击与故障的高发地。经典故障症状很有辨识度：网络明明通着（QQ 还在线），网页却全部打不开，报「找不到服务器」——号码簿坏了，不是路断了。换一个公共 DNS 服务（如国内多家厂商或国际公共解析服务提供的地址）常能立刻恢复。
P: DNS 记录还有一种常见变动叫负载均衡：同一个域名在不同时刻解析出不同的 IP，把海量访问摊到多台服务器上。所以你每次连接的可能不是同一台机器——这不是故障，而是设计。大型网站就是这样扛住节假日的访问洪峰的。
P: 更阴险的威胁是 DNS 劫持：把解析结果偷偷改向假网站，你输入的正确域名却被带到钓鱼页面。防御手段是给解析过程加密上锁（相关协议如 DoH、DoT 正在普及），以及养成核对网址的习惯——尤其涉及账号密码时，多看一眼地址栏永远不亏。

KC: 缓存的通用思想 :: 把昂贵操作的近期结果暂存在离使用者更近的地方，下次直接取用。缓存是计算机科学提高速度的第一法宝，DNS、浏览器、CDN 全是它的舞台。:: 试一试 :: 浏览器设置里清空缓存后重新打开常用网站，感受首次访问与二次访问的速度差。
P: DNS 的分层结构还带来一个工程美德：职责单一。根服务器只管「点 com 归谁管」这种粗颗粒问题，权威服务器只管自己域名的明细账。每一层都只需要记住很少的信息，加起来却覆盖全球。化整为零、各司其职——这个思想在计算机科学里随处可见。
P: 有个实验能把本章知识变成手感。运行 nslookup 加任意域名，看返回的地址；隔几分钟再来一次，注意响应时间的差异——第一次可能走了完整流程，第二次多半命中了缓存。再试一个从没访问过的冷门域名，对比耗时。三次观察胜过十遍背诵。
CALL: 动手推理 :: 学校机房断网后，为什么有些同学说「内网系统还能打开」？提示：想想哪些域名可能不需要出门查询，校园网自己维护了什么。

S: 小结与预告
P: 回顾本章：DNS 用分层接力完成全球规模的翻译，用缓存把成本压到毫秒级；它的故障有典型症状，劫持是需要警惕的安全面；nslookup 是随手可用的观察窗口。名字翻译完毕，包裹终于可以正式出发去找服务器对话了。
