T: 包裹与地址：分组交换与 IP

S: 为什么不整件寄送
P: 把一部长视频从服务器原封不动发给你的手机，可行吗？技术上很糟：这条巨型数据会独占沿途所有线路几分钟，别人全部卡死；中途哪怕坏了一个字节，整件作废重来。互联网的解法朴素而聪明——切块。数据被切成分组，每个包一般不超过一千多字节，各自独立上路。|mark:分组
@kp=packet-switching
FIG: 三条并行车道上行驶着许多小方盒卡车，每辆车顶写着「序号」和「目的地 IP」；其中一辆绕开标着「施工」的路段改走辅路；终点站台上几辆卡车按序号重新拼装 :: 包裹们各走各的路、抄近道避事故，到达后凭序号恢复原样
P: 每个分组都背着一张小名片——头部，写明目的地址、来源地址和序号。沿途的路由器只做一件事：读地址，查本地路由表，把包递给下一跳更合适的那位邻居。没有任何一台设备掌握全局地图，「问路式接力」却让包裹跨越几十台路由器抵达地球另一端。
P: 各包独立选路带来一个反直觉现象：先发出的包未必先到。走高速的直接到，绕路的晚半天——接收端按序号排队重组，缺号就等，超时未到的包则请求重发。这套「不可靠传输加末端补救」的制度看似将就，实则是整个互联网弹性的来源：任何一条线路中断，包裹自动改道。
CALL: 想一想 :: 视频通话偶尔出现花屏或卡顿，用分组交换的语言解释发生了什么？为什么它通常几秒内自动恢复？
P: 包裹要有收件地址，这就是 IP 地址的职责。最常见的 IPv4 地址是四段 0 到 255 的数字，形如 192.168.1.10，背后是三十二位二进制。全球可用的 IPv4 地址约四十三亿个，听起来很多，但在设备爆炸的今天早已不够分——这直接催生了两位救场选手。
@kp=ip-address
KC: IP 地址 :: IP 地址是设备在网络中的编号，路由器依据它投递分组；IPv4 为四段数字形式，IPv6 用更长的十六进制串提供了近乎无限的地址空间。:: 生活里的例子 :: 小区里每户都有门牌号，快递员按门牌逐层派送——IP 就是互联网的门牌系统。
P: 救场选手之一是 IPv6：地址扩到一百二十八位，数量号称能让地球上每粒沙子都联网。之二是 NAT 技术：一个家庭共享一个公网 IP，路由器在内部给每台设备发私有小号，出门时统一换装。你在自家看到的 192.168 开头的地址就是私有号段——全世界无数家庭都在重复使用它们，互不打扰。
KC: 路由器 :: 路由器是网络路口的快递分拣员：读每个分组的目的地址，查本地路由表，把包裹递给离终点更近的下一站邻居。:: 生活里的例子 :: 包裹从你家到外省要经过多个中转场，每个中转场只决定「下一站去哪」。
P: 分组交换还有一个隐藏福利：天然抗拥堵。高峰期某条路挤满了包裹，后来的包自动选空闲路线；就算个别包在路上丢了，只需重传那一小块，而不必整部视频从头再来。互联网从不追求每一步完美，而是用机制消化不完美。
P: 动手看看自己的地址。在系统网络设置或命令行输入 ipconfig（Windows）或 ip addr（Linux 与 Mac），找到 IPv4 一行；再搜索「我的 IP」，看到的是你家的公网出口地址——两者不同正是 NAT 在工作的证据。观察比背诵更能建立体感。
CALL: 动手实验 :: 运行 tracert（Windows）或 traceroute（Mac/Linux）加任意网站域名，数一数经过多少个中间站，最慢的一跳出现在哪里？

S: 小结与预告
P: 回顾本章：切块运输让线路共享、故障可绕行；分组带头部独立选路，接收端按序重组补漏；路由器问路式接力不需要全局地图；IP 地址是门牌制度，NAT 与 IPv6 解决了地址荒。
P: 不过你可能已经发现一个悬而未决的问题：包裹上写的地址是一串数字，而你输入的却是 www.example.com 这样好记的名字。数字和名字之间是谁在翻译？下一章介绍互联网的电话簿——DNS 系统。
