T: 小项目：猜数字游戏

S: 项目蓝图
P: 前四章你集齐了三样法宝：print 和变量负责说话与记事，条件判断负责选择，循环负责重复。这一章不再学新语法，而是把它们组装成一件真正的作品——猜数字游戏。计算机随机想一个 1 到 100 之间的数，你来猜，它提示大了还是小了，直到猜中为止。|mark:猜数字游戏
P: 动手之前先当一回建筑师：把大目标拆成小步骤。第一步，让计算机生成一个随机答案；第二步，请玩家输入一次猜测并给出提示；第三步，把第二步包进循环反复进行；第四步，统计次数并在猜中时结束。任何程序都可以这样切成小块再逐个击破——这个方法比语法本身更值钱。
@kp=random-number
KC: 随机数 :: 随机数是无法提前确定的数。Python 的 random 模块能生成指定范围内的整数，「random.randint(1, 100)」会给出 1 到 100 之间任意一个数，两端都包含。:: 试一试 :: 连续运行「print(random.randint(1, 6))」几次，结果就像掷骰子一样变化。
S: 第一步：让计算机想一个数
P: 先写最核心的两行：「import random」和「answer = random.randint(1, 100)」。第一行是借工具：random 是 Python 自带的随机模块，import 相当于从工具箱里把它取出来放到桌上。第二行调用工具生成答案存进变量 answer。运行后打印 answer 多试几次，你会看到每次都不同——这就是游戏的灵魂。
P: 光有答案还不够，得让玩家提交猜测。新工具 input 登场：「guess = int(input("请猜一个数字："))」。input 会把括号里的文字显示成提问，然后停下来等玩家敲键盘，玩家按下回车后，输入的内容被交给左边。注意外层包着的 int：input 拿到的一切都是字符串，必须转换成整数才能和答案比大小。
KC: int 类型转换 :: int 能把看起来像数字的字符串转换成真正的整数，「int("13")」的结果就是 13。input 返回的永远是字符串，想拿它比较大小或做算术，必须先套一层 int 转换。:: 试一试 :: 「print(int("13") > 9)」会显示 True。
CALL: 想一想 :: 如果玩家不套 int 直接拿输入的字符串和数字比较会发生什么？回忆第二章「"3" 加 "5" 等于 "35"」的教训，再决定要不要亲手试一下这个报错。

S: 第二步：判断与循环
@kp=condition-if
P: 拿到 guess 之后用条件判断给反馈：「if guess > answer:」打印「太大了」，elif 判断「guess < answer」打印「太小了」，else 打印「猜中了」。这三条岔路和第三章的成绩等级如出一辙，只是这次比较的对象换成了两个变量。
P: 接下来把「猜一次」升级成「猜到中为止」。上一章说过，「while True:」加 break 正适合不知道要重复多少次的场合。整体骨架是：循环每轮先要一次输入，再走一遍三条岔路；猜中那轮执行 break 跳出循环。缩进在这里再次立功——哪些行属于循环、哪些属于 if，全靠开头的空格说清楚。
FIG: 流程图：起点连着方框“生成 1~100 的随机答案”，进入菱形“输入猜测”，随后是菱形“太大？”与“太小？”两条回路箭头绕回输入处，“恰好相等”的箭头通向方框“显示恭喜与次数”后到达终点 :: 猜数字游戏主循环：猜错绕回来继续，猜中才放行
P: 最后加一点仪式感：建变量 count 从零开始，每轮循环加一，猜中后打印「你一共猜了 count 次」。想再进一步，可以在开头打印欢迎语、在结尾根据次数评价玩家的水平，比如十次以内算运气与直觉俱佳。这些小装饰不影响逻辑，却让作品有了温度。

S: 完整代码与调试
P: 把零件拼起来，完整程序大约十几行：import random 开头，answer 与 count 两个变量就位，「while True:」里依次完成输入、转换、计数、三分支判断，命中 else 时打印恭喜与次数并 break。建议先别看参考实现，自己照着蓝图逐块写完再对照——卡住的地方才是真正学到的地方。
P: 第一次运行几乎一定会遇到一两个报错，这不是坏事，而是本章隐藏的必修课：漏冒号是 SyntaxError，忘了 int 转换会得到大小比较的 TypeError，缩进不对会报 IndentationError。逐条读提示、定位行号、修正重跑，这个循环本身就是程序员每天的真实工作。
P: 运行成功后，把这局游戏玩三次，观察两件事：答案每次不同，说明随机模块在起作用；提示方向始终可靠，说明分支逻辑严密。然后把 randint 的范围改成 1 到 10 试试难度变化，或者规定最多只能猜七次、超次数就提前结束——这两个改动都是对你理解程度的真实检验。
P: 回顾整本书：第一章你学会了让程序开口说话，第二章给它装上记忆，第三章教会它做选择，第四章让它不知疲倦地重复，第五章你亲手把这一切组装成了自己的作品。顺序、分支、循环三大结构从此归你指挥，它们是所有编程语言共同的地基。
