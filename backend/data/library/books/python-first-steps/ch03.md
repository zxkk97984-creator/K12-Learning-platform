T: 条件判断：让程序学会做选择

S: 程序的岔路口
P: 出门之前你会看一眼天气：下雨就带伞，晴天就戴帽子。你每天都在根据情况做选择，但到目前为止我们写的程序还不会——它们只会从第一行老实执行到最后一行。这一章要教程序学会拐弯，靠的就是条件判断。|mark:条件判断
@kp=condition-if
KC: if 语句 :: if 语句先检查一个条件是否成立：成立就执行缩进的代码，不成立就跳过去继续往下走。它是程序里最常见的岔路口。:: 试一试 :: 「if score >= 60: print("及格")」在分数够 60 时才会打印这句话。
P: 最基础的写法长这样：「if score >= 60:」，下一行缩进后写「print("及格")」。逐字翻译成人话就是：如果 score 大于等于 60 成立，就执行下面缩进的那句。注意行尾有个英文冒号，它像在说「接下来是我的地盘」。上一章埋下的伏笔在这里兑现了——大于号比较两个数，得到的正是 True 或 False。
FIG: 流程图：一个菱形框里写着“score ≥ 60 ?”，右侧标着“成立”的箭头通向方框「打印及格」，下方标着“不成立”的箭头绕过方框直达出口，两条路最后汇合到“继续后面的代码” :: if 就像岔路口的指示牌：条件成立走这条路，不成立走另一条
P: 这里必须认真介绍一位新规矩：缩进。Python 不用大括号圈住代码范围，而是看每行开头的空格。if 下面想受它管辖的代码，统一向右缩进四个空格；缩进相同的算一伙，顶格不缩进的就脱离了管辖。缩进不是排版爱好，而是语法本身，多一格少一格都会报错。
CALL: 想一想 :: 为什么计算机要用缩进来划分「哪些代码归 if 管」，而不是像人一样自己理解？提示：回忆第一章说的，计算机只认精确指令。

S: 否则怎么办
P: 只会「成立时做什么」还不够。成绩低于 60 分的同学也需要一句安慰，这时请出 else。「else:」后面同样缩进写代码，意思是「前面条件都不成立时，就走我这条路」。if 和 else 像跷跷板两端，每次必然走其中一头，绝不会两头都走或两头都不走。
P: 把它们拼在一起就成了一次完整的二选一：「if score >= 60: 打印及格」，接着「else: 打印再加油」。无论 score 是多少，程序都恰好选中一条路。你可以把 score 改成 59 再运行一次，观察输出如何变化——亲手换数字试错，是理解分支最快的办法。
P: 现实中的选择常常不止两档。九十以上是优秀，六十到八十九是及格，六十分以下要加油，这就需要 elif（else if 的缩写）来增加岔路。「if score >= 90:」「elif score >= 60:」「else:」三个依次排队，程序自上而下检查，命中哪一条就执行哪一条，剩下的全部跳过。
P: 排队顺序大有讲究。如果把「elif score >= 60」放在「if score >= 90」前面，一个 95 分的同学会先撞上第二条路被误判成及格。所以条件要从严格到宽松排列。另外别忘了那个经典陷阱：判断相等要用两个等号「==」，单个等号「=」是赋值，两者长得像但职责完全不同。
KC: 比较运算符 :: 比较运算符用于判断两个值之间的大小或相等关系，运算结果永远是一个布尔值。常见的六个符号：大于、小于、大于等于、小于等于、等于、不等于。:: 试一试 :: 「print(3 != 5)」会显示 True，因为 3 确实不等于 5；而「print(3 == 5)」显示 False。
CALL: 想一想 :: 一个 100 分和一个 59 分的程序输入，分别会走过上面三岔口的哪几条检查？在纸上画出它们的路线，再看下一节的组合条件。

S: 更聪明的条件
P: 有时一个条件不够用。「成绩大于等于 80 并且出勤满 30 次」才能拿奖状，这种「并且」「或者」可以用 and 和 or 表达：「if score >= 80 and days >= 30:」。and 要求两边同时成立，or 只要求至少一边成立，not 则负责把成立翻转为不成立。
P: 该动手了。请写一个「穿衣提醒」小程序：建一个变量 temperature 存入今天的气温；如果低于 10 度，打印「穿羽绒服」；10 到 20 度之间，打印「加件外套」；超过 20 度，打印「短袖就好」。写完故意改几个温度值反复运行，确认三条路都走得通。
P: 回顾本章：if 是程序的岔路口，elif 负责增加岔路，else 兜底接住所有剩余情况；缩进决定了谁归谁管；and、or、not 能把简单条件拼装成复杂条件。你的程序已经会「看情况办事」了，但它每次只能判断一遍，想让同一个判断重复一百次怎么办？总不能复制粘贴一百遍吧。
