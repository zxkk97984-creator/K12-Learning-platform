T: 算法是什么：从菜谱到伪代码

S: 一个古老而现代的词
P: 你每天至少执行几十个算法而不自知。早上决定先穿哪只袜子、导航软件计算最快路线、考试时先做会做的题——凡是「为达成目标而设计的明确步骤」，都是算法。这个词听起来高深，内核却朴素得像一份菜谱：输入食材，按步骤操作，输出一道菜。|mark:算法
@kp=algorithm-definition
KC: 算法定义 :: 算法是为解决一类问题设计的明确、有限的操作序列：每步无歧义，总体能终止，并对一类输入普遍有效。:: 生活里的例子 · 泡茶的步骤（烧水、温杯、投茶、注水、等待）对任何一种绿茶都适用，不挑具体哪一天。
P: 注意定义里的三个关键词。明确：每一步不能有「适量」「差不多」这种模糊表述，计算机没有生活常识兜底；有限：必须在有限步后结束，死循环不算合格算法；通用：解决的是一类问题而非某一次的具体情况。菜谱常在第一点不及格——「盐少许」对人是提示，对程序是灾难。
P: 算法与程序的分工值得分清：算法是思路，程序是用某种语言写出的实现。同一份快排思路可以用 Python、C++ 或 Java 表达；衡量一个想法的好坏时，我们讨论的是算法层面的性质，而不是某种语言的语法细节。这也是为什么面试考算法而不考背语法。
CALL: 想一想 :: 「把这首诗读三遍」和「把这学期错题都弄懂」哪个更像合格算法？用明确、有限、通用三个标准逐一检验。

S: 用伪代码思考
P: 描述算法有一件趁手工具：伪代码。它不是真正的编程语言，没有固定语法，只用接近自然语言的结构把步骤写清楚，变量名和缩进随意但逻辑必须严格。它的价值在于让思考脱离语言细节——先用伪代码想通，再翻译成任何语言都不难。|mark:伪代码
P: 举个最小例子：求一组数中的最大值。伪代码可以这样写——令 max 等于第一个数；对剩余每个数 x：如果 x 大于 max，就把 max 更新为 x；循环结束后输出 max。五行字，任何学过编程的人都能读懂，也能直接翻成代码。写伪代码的过程就是逼自己想清边界的过程。
FIG: 一张对比图：左侧是流程化的中文菜谱卡片（步骤一、步骤二……），中间箭头指向右侧一段缩进整齐的伪代码块（含「对于每个」「如果…则」结构），两者之间标注「一一对应」 :: 从菜谱到伪代码只有一步之遥：去掉模糊词，补全判断与循环
P: 同一个问题往往有多种正确算法，这是本书最重要的起点观念。求最大值可以正着扫一遍，也可以两两比较淘汰；去图书馆借书可以先查目录再直奔书架，也可以逐排浏览。正确性相同，效率可能天差地别——于是「哪个更好」成为算法研究的核心问题。
P: 怎么评价好坏？直觉会说跑得快的更好，但秒表不可靠：同样一个排序，一百个数据和一千万个数据的耗时毫无可比性；不同电脑上的计时也不公平。我们需要一把不受机器和运气影响的尺子——这个悬念留到第四章揭晓。在此之前，先认识两位最经典的老朋友。
KC: 伪代码 :: 伪代码是用接近自然语言的结构描述算法步骤的工具：没有固定语法，但逻辑必须严格。先想通伪代码，再翻译成任何语言都不难。:: 试一试 :: 用伪代码写「交换两个变量的值」，注意中间需要几个临时变量。
CALL: 动手试试 :: 用伪代码写出「统计一组成绩中不低于 60 分的人数"，注意检查：空列表时会输出什么？你的步骤是否对所有输入都成立？

S: 小结与预告
P: 回顾本章：算法是明确、有限、通用的步骤序列；伪代码是思考算法的语言工具；同一问题存在多种解法，效率差异巨大，我们需要客观的评价标准。工具箱已经备好，下一章请出第一位主角——排序。
P: 排序是计算机科学里被研究得最透彻的问题之一，从笨拙的冒泡到优雅的归并，一部排序史就是半部算法思想史。下一章，我们从最直觉的方法开始动手。
