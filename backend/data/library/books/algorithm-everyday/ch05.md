T: 权衡与拆解：贪心与动态规划

S: 直觉的策略：贪心
P: 找零问题开场：顾客付一百元，消费三十七元，要找六十三元。你会怎么凑？几乎不假思索——先给最大的五十，再给十，再给两块一元。每一步都拿当前面值最大的硬币，绝不回头。这种「每步取当前最优」的策略叫贪心算法，它简单、快、直觉上无懈可击。|mark:贪心算法
@kp=greedy-algorithm
KC: 贪心算法 :: 贪心算法在每一步选择当前看起来最优的选项，且从不撤销。它速度快，但只在问题结构保证「局部最优能连成全局最优」时才可靠。:: 生活里的例子 · 活动安排问题：每次选结束最早的活动，能给一天塞进最多场次。
P: 但贪心会翻车。改一下币值系统：只有 1 元、3 元、4 元三种硬币，凑 6 元。贪心先抓 4，再抓 1、1——共三枚；而最优解是 3 加 3，只要两枚。第一步的「最优」堵死了全局最优的路。这个反例说明：贪心的正确性不是白来的，需要证明问题具备特殊结构——局部选择不会破坏后续的最优可能。
P: 那怎么判断贪心能不能用？实用做法是找反例：构造一个小规模输入，手算贪心结果与暴力最优结果对比。找不到反例再试着给出论证（如兑换标准币值的贪心正确性）。记住态度：贪心是「快而险」的策略，用它之前先过反例这一关。
CALL: 想一想 :: 考试策略「先做所有会做的题再做难题」在什么情况下吃亏？构造一个具体的分数与时间场景验证你的判断。

S: 驯服指数爆炸：动态规划
@kp=dynamic-programming
KC: 动态规划 :: 动态规划把大问题分解为相互重叠的小问题，将每个小问题的答案存入表格，后续直接查表复用，从而避免重复计算。:: 生活里的例子 · 记账本记下每月结余，年底算总额时直接翻账本相加，而不是重算每个月每一笔。
P: 看一个熟悉的数列：斐波那契——每一项等于前两项之和。朴素递归写法极简短，但复杂度是指数级的 O(2ⁿ)：算第 50 项要做上万亿次加法。毛病出在大量重复劳动——求 f(50) 要算两次 f(48)、三次 f(47)……同一个子问题被翻来覆去重算了亿万遍。
P: 动态规划的解法朴素到令人发笑：准备一张表，从 f(1)、f(2) 开始自底向上逐行填写，每格只算一次、随取随用。n 个格子填完，答案出炉，总代价 O(n)。同样的数学关系，仅仅因为「把算过的存下来」，就从宇宙级耗时降到瞬间完成。这就是记表的魔法。
FIG: 左右对照图：左侧一棵递归调用树疯狂分叉，相同节点（如 f(5)）反复出现并标红；右侧一张一维表格从左到右依次填入 1, 1, 2, 3, 5, 8……每个箭头只指向已填好的格子 :: 递归树里遍地重复，表格让每个子问题只算一次——空间换时间的经典交易
P: 判断一个问题能否用动态规划，看两个特征：重叠子问题——拆出来的小问题会反复出现；最优子结构——大问题的最优解由小问题的最优解拼成。凑硬币换个问法就符合：「最少多少枚硬币凑出 n 元」可由「凑 n−1、n−3、n−4 元的最少枚数」推出来。于是同一张表又能派上用场。
P: 从贪心到动态规划，你其实见证了策略光谱的两端：前者赌问题结构友好，一步到位、绝不回头；后者老老实实记录一切、稳扎稳打。工程中的高手不是站队某一方，而是识别眼前的问题落在光谱哪个位置——有贪心性质就用贪心，没有就上动规，实在不行再谈近似与启发式。

S: 全书回顾
P: 五章一路走来：算法是明确有限的步骤，伪代码是思考它的语言；排序展示了蛮力与分治的天壤之别；二分揭示了有序性的对数红利；大 O 教我们用增长的形状评价一切；贪心与动规则给出了面对复杂决策时的两套哲学。这些思想不属于某个编程语言，它们属于任何需要「想清楚再做」的场景。
P: 最后送你一句话作为书签：算法的本质不是炫技，而是在有限资源里寻找更聪明的权衡。愿你今后面对任何庞大任务时，都能习惯性地问三个问题——它的规模有多大？我的方法是什么形状？有没有更聪明的形状？
